# Glide · 商业化产品规划 v1

2026-09-20 · 提案 / 尚未发布 · iPhone 与 iPad 优先

## 1. 产品判断

**定位：把自己的片库，变成随手可刷的私人影院。**

核心承诺是“找到一个想看的目录，立即看见里面的所有视频，然后连续观看”。首次版本聚焦已有 Jellyfin / NAS 的个人用户，尤其是旅行影像、纪录片、演出和私人收藏的重度观看者。第二人群是希望在 iPad 上浏览家庭影像的人。

与传统播放器的差异集中在三个地方：任意目录即播放范围；文件夹与后代视频同时可见；左右刷片与精确观看共存。Infuse 已覆盖广泛格式、媒体服务和多设备体验，第一阶段应集中打磨上述差异，而不以协议和编解码器数量作为主要竞争指标。[Firecore 官方介绍](https://firecore.com/infuse)

工作名称继续使用 Glide；正式上架前完成商标、App Store 同名与域名检查。首发中文、英文；地区从实际用户与支付配置验证后决定。以下定价、排期和指标均为待验证假设，不是市场数据或发布承诺。

## 2. 首次价值与留存闭环

首次启动 → 选择体验演示或连接 Jellyfin → 验证连接 → 选择媒体库 → 看到文件夹及全部视频 → 从封面开始播放 → 左右换片 → 收藏目录或建立片单 → 再次打开回到该范围及进度。

导航四项：片库、收藏、离线、设置。“片库”内切换来源与媒体库；“收藏”包含收藏视频和固定目录；离线在未启用时展示能力说明，设置承载连接管理、播放偏好与 Pro。播放器全屏，返回恢复原列表滚动位置、筛选和目录。

核心留存来自固定目录、继续观看和未看片单。无需额外注册 Glide 账号即可连接自有服务器。不插入信息流广告、不售卖影视内容，也不建立公开内容推荐流。

| 片库浏览 | 层级目录、后代视频平铺、分页 | 缩略图缓存、取消旧请求、去重、滚动恢复、按范围搜索与筛选、全量计数语义 | P0 |

## 4. 商业模型建议

首发采用 **免费基础版 + Pro 一次购买**，先验证付费意愿。现有本地工具型价值更适合买断；未来若推出持续成本明确的云服务，再独立评估订阅，避免仅因“商业化”而增加订阅。

| 免费版 | Pro 规划 |
|---|---|
| 1 个新连接来源、完整目录浏览 | 多来源管理 |
| 任意目录开刷、顺序与随机 | 离线下载和容量管理 |
| 原画与1080p、旋转、基本手势 | 智能片单、批量收藏与整理 |
| 收藏、继续观看、基础字幕音轨 | 按目录保存偏好、手势自定义 |
| 无广告、无播放次数限制 | 后续符合本次购买范围的更新 |

建议验证价 **¥98 一次购买**，通过访谈或封闭测试比较 ¥68 / ¥98 / ¥128 的接受度；实际售价必须来自 StoreKit 展示的本地价格，原型中的 ¥98 仅为设计占位。老测试用户已有来源不强行锁定；付费墙只在主动使用新增 Pro 能力时出现，不打断播放。购买页清楚列明已可用权益，尚未交付能力不能计入销售承诺。用一个非消耗型 IAP entitlement 控制权益，恢复购买、交易待批准、退款撤销、离线已购状态都有明确状态机。

Apple 提供免费加内购等商业模式和内购配置机制，正式发布按目标商店当时规则核对。[商业模式](https://developer.apple.com/app-store/business-models/) · [内购配置](https://developer.apple.com/help/app-store-connect/configure-in-app-purchase-settings/overview-for-configuring-in-app-purchases)

不将用户 NAS 转码包装成 Glide 提供的付费云算力。首发不存储或代理用户视频，不承担视频分发带宽。

## 5. 关键交互契约

- **范围**：媒体库/目录默认包含后代；工具条可切换“含子目录 / 仅当前层”。标题、数量、搜索、筛选与播放队列使用同一范围快照。切换范围取消旧请求并重置队列预览。
- **搜索**：商业版默认搜索整个当前范围，显示“正在搜索”，不再将已加载卡片搜索误称完整搜索。WebDAV 无服务端检索时说明索引进度；搜索失败保留已有结果。
- **队列**：点封面从该片开始。顺序模式按当前排序向后；随机模式选中片置首，剩余无重复。到末尾默认停止，可显式开启循环。手动前后切换和自然结束共用队列规则。
- **大目录**：展示首批即能浏览；顺序模式可渐进准备，随机模式先收齐轻量 ID 再洗牌。必须明确“准备中”，可取消，不能偷偷只随机首批。
- **手势**：单指水平滑动只在未缩放/播放画面区域换片；进度条拖动只调整时间。双指缩放、双指平移；放大时换片需回到适应或显式下一片。返回边缘手势优先，锁屏保留解锁入口。所有手势有按钮替代。
- **画质**：自动/原画/1080p 独立于旋转与缩放。切换保留时间、暂停和倍速；失败保留上一可用方案并给重试入口。选择项与实际播放分辨率分别显示。
- **恢复**：返回列表保持滚动位置；重新进目录沿用偏好；播放进度在离开/暂停/定时上报，跨设备冲突按服务器时间和会话规则处理。

## 6. UI 方向：Quiet Cinema

石墨黑底、暖白文字、雾绿强调色。封面占主要面积，服务端技术信息放入详情。主标题简短，不在片库上方放大段营销文案。文件夹是可横向浏览的紧凑入口，下面直接平铺视频。海报用2:3；旅行/家庭原始素材可以改成16:9截图模式，避免裁剪内容成为识别障碍。

交付页面：媒体库总览、目录与平铺、沉浸播放器、播放设置面板、来源连接、收藏、离线、Pro、iPad 双栏。原型内服务器和影片均为虚构演示数据；封面为原创 AI 生成素材。原型切片、选择范围、顺序/随机、收藏、画质面板可交互，连接和购买仅模拟，不真实发请求或扣款。

## 7. 版本路线与发布门槛

假设 1 名 iOS 工程师全职、设计/QA 部分投入；依赖风险另计。总量约 10–14 周，具体由 P0 播放兼容性验证后重估。

| 阶段 | 时间假设 | 交付 | 退出条件 |
|---|---|---|---|
| 设计验证 | 第1–2周 | 本文、可交互UI、5–8位目标用户访谈 | 多数参与者无需讲解可连接/选范围/刷片；验证购买动机 |
| 稳定核心 | 第3–5周 | 新UI原生落地、缓存/索引、播放状态机、字幕音轨、iPad | 核心路径自动化通过；无已知阻断故障 |
| Pro闭环 | 第6–8周 | 下载、多来源权益、智能片单、StoreKit测试 | 购买/恢复/撤销/离线权益全覆盖；付费能力实际可用 |
| TestFlight | 第9–11周 | 30–50名自愿用户，真实不同NAS/网络/素材 | 达成以下质量门槛，整理支持文档 |
| 上架准备 | 第12–14周 | 中英素材、审核演示、隐私/支持入口、定价 | 审核资料齐备、回滚方案与支持响应就绪 |

目标门槛（待实测，不代表现状）：无崩溃会话≥99.8%；受支持样本播放成功率≥98%；固定基准条件下局域网直放首帧p95≤2秒，预备好资源后切片p95≤1秒；1万条元数据片库不出现重复/越界/明显主线程卡顿。转码起播单独量测，不能与直放混算。

验收矩阵包括 iPhone/iPad、横竖屏与分屏、Wi-Fi/蜂窝/断网、令牌过期、无权限、无封面、空目录、1万条目录、低磁盘、音频中断、字幕切换、1080p转码失败、播放连续切换100次、购买恢复及退款撤销。真机热量/内存/耗电必须验证，模拟器通过不足以上架。

## 8. 技术演进与成本

保留 SwiftUI + AVPlayer，拆成 SourceAdapter、LibraryRepository、ScopedQuery、QueueCoordinator、PlaybackSession、DownloadManager、EntitlementStore。Jellyfin/WebDAV 共用范围模型，协议适配器独立。封面缓存与元数据分页设上限；浏览和预取可以取消；只预取邻近视频少量资源，蜂窝默认关闭。

当前全量收集后播放适合原型，商业版应先完成大目录队列设计。原型中的 UserDefaults 收藏/进度演进为可迁移数据库；Keychain继续存令牌。引入协议测试桩、网络失败注入、UI旅程测试和真机性能基线。未验证收益前不引入独立后端，不为遥测采集影片名称、目录路径、地址、令牌或视频内容。

预算拆分为工程/设计QA人力、开发者账号、真机与NAS测试、客服、商店渠道成本。下载和播放走用户自有服务器；任何云同步/第三方字幕元数据服务单独核算协议、许可和调用费用。不能将一次买断收入全部视为利润，需要预留后续兼容维护与支持成本。

## 9. 运营、隐私与验证

以连接完成率、首播完成率、次周回访、固定目录使用率和主动触发Pro后的购买率验证产品。先访谈与本地诊断，再引入用户可选择的最小化事件统计；只保留匿名的能力事件、时延区间、错误分类。事件不得包含片名/路径/主机/凭据。默认崩溃日志也做脱敏，提交诊断前展示内容。

发布资料包含真实可用的演示媒体库或完整演示模式、恢复购买、支持邮箱/隐私页、数据删除入口、截图与实际功能一致；需要账号的能力按实际设计处理账号删除。审核指南要求可供审核的访问或演示资源。[Apple 审核指南](https://developer.apple.com/app-store/review/guidelines/)

首轮测试问题：用户是在随意找片还是连续看完？喜欢目录、海报还是截图？是否需要多来源？离线和智能片单哪个能带来真实付费？记录一次完整任务的操作数和失败原因，再调整优先级。

## 10. 本轮交付边界

本轮交付产品规划、视觉系统和可交互设计稿，原生App现有功能未改动。原型中的下载、支付、连接诊断、全范围搜索和部分偏好为设计状态，不能作为已上线能力。下一实施顺序：先新片库UI与范围模型，再播放器状态与设置面板，再Pro能力与商店闭环。
