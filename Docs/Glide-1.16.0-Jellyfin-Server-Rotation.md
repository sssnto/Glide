# Jellyfin 12.2 服务器旋转保存 · 构建 12／插件 1.1.0

当前开发版本为 1.1.0，增加列表批量旋转、持久化串行队列和按保存结果刷新的预览帧，见 [批量需求与验收](Glide-1.16.0-Batch-Rotation.md)。用户 2026-11-11 已确认上一版 1.0.3 在实际 NAS 可完成旋转与保存。以下为此前文件发布安全性修复的记录。实际 NAS 的媒体卷为 SMB2；旧代码在提交时仍持有原文件共享读取句柄。1.0.3 关闭全部自持原片句柄，检查原片读写访问和显式独占锁，释放并关闭该锁后才发布。检查失败在替换前停止，客户端拒绝 1.0.0–1.0.2 的保存。实际 SMB2 前后回归与大文件测试见 最新验收（本机历史资料）。以下 1.0.1／1.0.2 内容为历史过程，不能代替最新状态。

1.0.0 在用户 NAS 上出现原路径缺失，用户已从保留的 `.bak` 复制恢复并确认可播放。该版停止使用；1.0.1 加入实际目录原子交换检测、不覆盖的缺失原片恢复、独立管理员恢复页和具体失败编号。Glide 1.16.0（11）拒绝向 1.0.0 提交保存请求。新版的真实 NAS 保存验收待用户升级后用副本完成，不能用本地通过代替。见 事故修复验收（本机历史资料）。

1.0.1 已在用户 NAS 的原创短片上检出 `atomic_exchange_22`，在替换前安全拒绝，不能完成该 NAS 的保存。1.0.2 补充经过独立探测的同目录原生 rename：临时输出与原片位于同一父目录，原始备份仍保留；原生系统调用失败后不回退到覆盖复制。优先交换，交换不适用时选择该方式，两者都未通过则拒绝。真实 NAS 新模式仍待用户安装 1.0.2 后验收，见 同目录保存记录（本机历史资料）。

## 用户流程

Glide 播放 Jellyfin 在线视频时，从播放设置打开“视频方向与保存”。左右旋转仍在当前画面预览，控制器不转动。Glide 检查服务器插件和当前账号权限，确认框显示当前媒体版本的文件名。点击“保存到服务器原文件”后，手机只发送媒体 ID、媒体版本、文件版本指纹、方向和唯一请求 ID。

服务器任务备份、修正、校验并替换文件，Glide 显示处理阶段，完成后在原进度重新打开，保持播放／暂停状态、倍速及音轨／字幕选择。任务被接受后可退出播放器，服务器继续运行。重新进入同一媒体版本的方向面板可继续查看任务；响应不确定时沿用本机已持久保存的请求 ID，核对接口只读检查，不重复旋转。

“从备份还原”也是服务器任务。当前内容和保存结果不一致时拒绝还原，避免覆盖后来修改的文件；还原前也会备份当前版本。Jellyfin 没安装插件、账号无权限或格式不支持时，仍可预览方向，但不能远程保存。不会静默转为手机下载、上传。

WebDAV 的原有保存路径保留，Emby、SMB、本地文件、离线副本、STRM、片段、画中画和外部播放不会通过此插件修改原文件。

## 服务端实现

独立项目 `Server/Jellyfin.Plugin.GlideToolkit`，使用 .NET 10，Jellyfin.Controller／Model 固定为 12.2.0。托管 DLL 在官方 Jellyfin 12.2 Linux 容器加载，iOS 不链接服务端依赖。安装与配置见 [服务器说明](https://github.com/sssnto/GlideToolkit)。

插件通过 Jellyfin 用户身份校验与媒体库管理器解析当前媒体 ID，精确匹配指定媒体版本，不接受客户端路径或 URL。默认仅管理员可写，支持显式普通用户授权及允许目录；重新核验任务执行和替换前的权限与文件路径。拒绝符号链接、网络媒体来源、非库内文件及多视频轨。

第一版支持 MP4／MOV／M4V 的 90°／180°／270° 显示矩阵变更；保留原有变换并进行角度组合。只改变 `tkhd` 的 36 字节矩阵，不重新编码，不重封装，全部音视频、字幕和其他元数据字节保持原样。

任务单队列串行执行，每文件只允许一个活动或待核对任务。服务器当前仍有播放时先等待，等待超时则拒绝替换。处理前检查服务器空间；在原文件同文件系统内生成备份和临时文件，验证完整 SHA-256 与矩阵外字节，保留 NAS 的文件所有者、权限及扩展属性。先用随机小文件探测交换；不能使用时，另在原视频同一父目录检测原生 rename 的覆盖和源消耗语义。使用原文件版本和完整摘要复核，先同步持久日志与临时文件，再以选定方式原子发布，最后核对完整摘要；不回退到覆盖复制。API 的 publicationMode 仅包含方式名，不含路径。

数据卷中的事务日志保留服务器内部路径和摘要，不通过 API 返回；备份位于媒体旁的 `.glide-rotation` 私有目录，使用 UUID 文件名与 `.bak` 扩展名，不作为媒体导入。日志和备份需要保留，第一版不自动清理历史备份。

文件系统锁无法约束不遵守锁的外部写入工具，因此不把替换前检查表述为跨全部程序的文件系统 CAS；应避免其他程序同时编辑同一原片。服务器在替换前中断时标记任务失败且不修改原文件；替换附近中断则在重启或显式核对时只读比较输入、输出和备份，不能确认时阻止重复操作。

## 协议 v1

所有路由沿用 Jellyfin 登录认证。JSON 显式使用 camelCase。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/GlideToolkit/Capabilities` | 协议、可用性、允许格式 |
| GET | `/GlideToolkit/Items/{itemId}/Rotation?mediaSourceId=…` | 当前文件名、长度与版本指纹 |
| POST | `/GlideToolkit/Jobs` | 提交带幂等 ID 的旋转或还原任务 |
| GET | `/GlideToolkit/Jobs/{jobId}` | 查询任务阶段和结果 |
| GET | `/GlideToolkit/Items/{itemId}/Jobs?mediaSourceId=…` | 重连后查询当前版本的任务记录 |
| POST | `/GlideToolkit/Jobs/{jobId}/Verify` | 只读核对不确定结果 |
| GET | `/GlideToolkit/Recovery/Jobs` | 管理员查询异常任务，不依赖片库条目 |
| GET | `/GlideToolkit/Jobs/{jobId}/Recovery` | 管理员检查原文件和备份的完整摘要 |
| POST | `/GlideToolkit/Jobs/{jobId}/RecoverMissing` | 显式确认后补回缺失文件，已有文件不覆盖；原片已手动恢复时核对并结束异常任务 |

持久任务状态包括接受中、排队、执行、提交中、完成、失败和等待核对。协议结果只包括 ID、状态、进度与错误代码，不包括原文件路径、备份路径或凭据。Glide 在 POST 前持久保存请求身份，断线后可用同一身份获取原任务；相同请求 ID 的不同内容被拒绝。

本地验收与已知部署边界见 记录（本机历史资料）。NAS 由用户手动安装插件后，再完成真实服务的最终验收。
