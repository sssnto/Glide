# Glide 1.3.0：本地兼容播放

开发版本 1.3.0（8），未发布。按用户要求，将已验证的 MobileVLCKit 3.7.3 接入主应用；WebDAV 增强继续暂缓。本批仅扩大本地播放范围，长期 SenPlayer 对齐不据此视为完成。

## 用户流程

首次仍用「系统播放」。打开本地视频后，在「播放设置 → 本地播放器」选择「兼容播放 · VLC」；应用重建当前播放器并保留当前位置和播放／暂停意图，后续本地视频沿用该选择。系统播放失败时，错误卡提供「尝试兼容播放」。也可随时切回系统播放；切换内核不改变队列顺序或家庭刷看的历史策略。

选择按当前解析资源判断：只有本地 file URL 且没有认证请求头才能交给兼容内核，包括已下载的本地文件；HTTP、Jellyfin 在线流及 WebDAV 继续走原生路线。选择偏好不能绕过该限制。画中画正在运行时不能切换。

## 本批实现

- 主应用与独立验证程序共用 `VLCPlaybackEngine`、公开 libVLC 时钟桥接和资源生命周期实现。
- 本地 MKV／AVI／改后缀文件进入独立解码路线；内嵌 ASS 和音轨可在通用设置中选择。支持程度落实到测试样例，不按容器名承诺全部编码。
- （2）随包提供离线中文后备字体，修复兼容字幕缺字方框。普通文本字幕使用注册字体，ASS 使用随包字体目录与默认家族兼容别名；不覆盖原字幕的布局和颜色。字体来源、修改与 OFL 许可证见 [依赖锁定](../Dependencies/SubtitleFont.json)。
- 实际出画面依据 decoded output 的 displayedPictures、非零视频尺寸及已附着窗口；元数据 ready 和时钟推进不能代替首帧。
- 暂停冷启动静音准备首帧，再进行待处理定位；定位取消、字幕回读与最新播放意图各有失效边界。
- 每次输入拥有独立画布；停止后保留播放器和文件租约至底层停止，再在后台释放解码对象，避免主线程等待与旧回调污染。
- 视频信息展示实际轨道检查；兼容检查不借 AVFoundation 的 isPlayable 阻止起播。诊断包含所用内核，不保存片源路径或认证信息。
- 控件按能力显示。VLC 路线不显示原生 PiP、AirPlay、时间轴缩略图和原生填满画面入口，也不显示无法测量的原生缓冲范围。双指缩放与刷看保持通用实现。

## SDK 与构建

构建（3）改进 Jellyfin 原画 4K／高码率网络视频的续播缓冲：已出画面且缓存不足时，原生播放器先蓄积约 6 秒媒体内容再续播，倍速目标最多 12 秒；平台缓存已满时允许以足够的较小缓存恢复，主动等待最多 15 秒，暂停、拖动和切换文件会取消。保持当前原画路由；普通低码率流沿用既有策略。诊断升级到 schema 7，增加片源码率／帧率、原生停顿、丢帧和续播时缓存；下载速率与片源码率分别记录。专项见 [Jellyfin 4K 验证](Testing/Glide-1.3.0-Jellyfin-4K-2026-10-16.md)。

构建（4）补充主动预装载：缓存等待期间显式请求 AVPlayer 准备播放管线，用户暂停、拖动、切文件和旧加载失效均取消。诊断 schema 8 在媒体时钟停止时仍刷新当前／上次等待时长、原生状态、缓存容量与 access-log 传输统计。新增匹配反馈负载的原创 4K／50 帧样例；本轮验证与实际限制见 [4K／50 帧复核](Testing/Glide-1.3.0-4K50-2026-10-16.md)。

构建（4）用户原片复测仍频繁缓冲，不能将 Jellyfin 4K 卡顿视为已解决。最新 [原片复测分析](Testing/Glide-1.3.0-4K-build4-user-followup-2026-10-16.md) 已记录两次主动等待未达到目标、当前供流观测及后续同内核离线对照步骤。

用户随后反馈离线播放流畅。构建（5）增加有界的原画传输恢复：原画直放主动蓄缓存无效后，在服务器明确支持时尝试一次保留视频的分段供流，维持位置和暂停意图；试用流无法起播时回到原画直放，避免由此次失败直接触发视频降档。无效主动等待在同一媒体项内不再重复。播放设置增加“尝试原画兼容”和针对 Jellyfin 离线副本的“在线播放”，保留原有下载；显式网络请求不会被新完成的离线副本覆盖。当前仍使用系统网络播放内核。[实现与验证](Testing/Glide-1.3.0-Original-Transport-2026-10-16.md)。用户原片随后确认：在线直放约 5–6 秒停顿，手动切为原画兼容后流畅。

构建（6）将原画分段的选择提前到开播前：Jellyfin 4K／声明码率至少 20 Mbps 的直放资源，服务器未明确拒绝时先协商保留视频的分段供流，响应仍须通过视频复制校验；失败返回直放一次。保留媒体版本、位置、倍速与暂停意图，离线优先及显式在线播放继续生效，候选下一集不预读直放媒体或提前启动 HLS。[实现与验证](Testing/Glide-1.3.0-Preferred-Transport-2026-10-16.md)。

构建（7）原片仍直放卡顿且手动入口消失；构建（8）修复协商标记与候选编码的误用：显式请求复制原视频，自动尝试失败后保留手动重试入口；设置显示实际启用状态，schema 9 独立保留试用结果和技术失败原因。[问题分析与验证](Testing/Glide-1.3.0-Transport-Retry-2026-10-16.md)。

分发修订：SDK 准备保留与每个 CPU 架构匹配的官方 dSYM，旧缓存自动迁移；Release 构建核对 framework 与 dSYM UUID，发布预检可通过 `--archive` 检查实际归档。用户 1.3.0（6）的失败归档已补齐同 UUID 符号并验证签名，尚未重新上传。[符号修复记录](Testing/Glide-1.3.0-MobileVLCKit-Symbols-2026-10-16.md)。

固定归档和 SHA256 见 [依赖锁定](../Dependencies/MobileVLCKit.json)。先运行 `python3 Scripts/prepare_compatibility_sdk.py`，再用 Xcode 打开现有工程。脚本验证官方归档后仅裁剪 CPU 架构：真机 arm64，模拟器 arm64／x86_64；不改解码源码。构建阶段检查 SDK 存在，自动嵌入并签名动态 framework。

设置中提供「开源组件」，包内包含版本、源码引用和 LGPL 2.1 文本。[源码材料清单](Dependencies/MobileVLCKit-3.7.3-sources.json)记录 VLCKit、libVLC 基线和补丁哈希；完整传递组件材料与正式分发复核仍是上架前工作，不能用当前基础声明替代。

`GlideCompatibilityQA` scheme 使用独立 Bundle ID 与名称，可与正式 Glide 并存。测试入口仅在 DEBUG 配置启用，固定读取 QA 沙盒中的原创素材目录，Release 不包含该入口。

## 验收与边界

开发验收、失败修订和真机长播数据见 [1.3.0 验证报告](Testing/Glide-1.3.0-compatibility-2026-10-15.md)。独立程序 50 次开关和 30 分钟 1080p 长播用于验证生命周期与基本稳定性；最终主应用的切换和 UI 单独验收，不能混用构建范围。

（2）的中文字形修复、复现画面和新增专项记录见 [中文字幕验证](Testing/Glide-1.3.0-CJK-subtitles-2026-10-15.md)；不把此前只含英文的 ASS 测试视为中文已覆盖。

当前没有兼容内核网络随机读取、PGS／SUP、字体附件与复杂 ASS 特效、HDR／杜比／多声道输出、原盘、PiP／AirPlay、后台音频、兼容预览的完整支持声明。没有真实用户片源，真机长播静音，人工听音与 iPad 真机仍待验证。上架前完成这些范围中计划对外承诺的专项及分发材料复核。
