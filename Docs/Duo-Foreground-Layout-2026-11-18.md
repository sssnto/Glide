# Duo 片库恢复与展开全屏修复

## 问题与修改

用户在 Duo 上从后台返回片库后，海报和文字被右侧系统栏遮挡。

共享 `AdaptiveMediaGrid` 原先测量 `LazyVGrid` 自身的渲染宽度，再用这个宽度生成固定列。当系统栏恢复、父容器提供更窄的可用区域时，旧列宽可能反过来撑大网格及其父容器，形成宽度反馈：内容无法按新的安全区域收缩。

在网格外明确添加接受父级宽度的弹性 frame（`minWidth: 0, maxWidth: .infinity`），并在这个 frame 上测量当前可用宽度。随后仍由原有列规划处理列数、折叠分区及无障碍字号。

没有通过重建根页面、固定侧栏宽度或额外叠加安全区域来修复；网格及卡片的身份保持稳定。

## 回归

## 展开播放默认全屏

原先 `PlayerView` 只要检测到 regular／regular 尺寸，就自动进入分区布局，并禁用轻点隐藏和自动隐藏控制器。控制区持续占用独立空间，导致展开 Duo 的视频区域明显偏小。

现在将“宽屏支持控制面板”与“用户选择显示面板”分开：每次进入播放器默认使用完整画布，控制器叠加显示、轻点显隐并按已有延迟自动收起。宽屏下可在“播放设置 → 打开控制面板”选择分区模式，面板内“全屏观看”可立即返回。折叠时自动使用覆盖式控制器。

播放会话、渲染层和画面交互状态仍由同一个播放器持有，布局切换不调用重新打开视频。没有更改视频比例的默认规则，竖版视频在横向屏幕中仍按比例显示。

`DuoPlayer-Fullscreen-03.xcresult` 在官方 Open 姿态通过：

- 默认画布的宽、高均超过应用窗口的 94%，隐藏面板按钮不可触达。
- 实际打开面板再返回全屏，画布恢复原尺寸；会话、渲染层身份、打开次数、暂停位置、音轨及 1.5 倍速全部保持。
- 开始播放后控制器自动隐藏；轻点画面可唤出，再次轻点可收起；播放时间继续推进。

自动化测试将隐藏延迟设为 8 秒，为 XCTest 查询和截图留出时间；生产环境仍使用原有用户设置。前两次测试分别因隐藏视图仍可被 XCTest 查询，以及 2 秒隐藏延迟与查询产生竞态而失败，不计为通过。

通过 Device Hub 的官方 Closed、Partially Open、Open 和 Rotate Right 按钮另做暂停播放连续性检查。展开画布为 867×635 点，折叠后为 382×644 点，展开旋转后为 669×835 点。各状态保持同一会话、1 次视频打开、第二音轨和 1.5 倍速，暂停位置差小于 0.15 秒，无播放错误。样例为原创素材，静音播放，不使用用户媒体或观看进度。

展开阶段的 XCTest 默认截图抓到了未激活显示屏，输出为黑图，因此不将这些黑图作为视觉证据。补充保存的 `Screenshots/05-player-partial.png` 和 `06-player-open-rotated.png` 来自活动内屏，已人工复核。片库展开阶段的结论依据 UI 自动化几何断言；此前外屏三轮恢复的有效截图仍保留。
