# 列表批量旋转与新预览 · Glide 1.16.0（13）／Toolkit 1.1.0

## 本次需求

上一版服务器旋转保存已由用户于 2026-11-11 确认可用。本次补齐列表识别与批量操作，不改变已经验证的 SMB 发布、备份与恢复机制。

1. Jellyfin 家庭视频／文件预览在旋转后生成当前文件的画面，避免继续命中原来的封面。列表增加独立方向状态，电影和节目保留原海报。
2. 在当前视频列表点右上角“选择”（或更多 → 批量旋转），原网格直接显示勾选标记，缩略图、标题和方向状态保留；底部选择左右 90° 或 180° 后一次确认，加入服务器队列。不再打开另一份选择列表。
3. “旋转任务”在当前列表菜单、电影／节目库菜单和设置中可达。详情显示每个文件的结果、当前阶段、进度、已保存／剩余／失败／取消／待核对数量。

## 交互与边界

- 保留当前网格、滚动锚点、搜索与收藏筛选，点按卡片改为勾选，长按可预览。电影在当前网格选择，节目在实际单集列表选择，系列封面本身不进入队列。
- 一次最多 1,000 个视频。“全选已加载”只选择当前加载并展示的媒体，不请求未加载分页或递归扫描全库。继续滚动加载后可追加勾选；超过上限会提示分批，不静默截断。选择可跨当前目录内的搜索结果保留，切换目录或季会退出选择。
- 批量功能仅连接 Jellyfin Toolkit 1.1.0+。WebDAV、Emby、离线文件和 STRM 不进入服务器批量队列；也不回退到手机下载、上传。旧插件 1.0.3 的单文件保存保持可用。
- 状态表示保存历史，不自动判断视频内容是否“正立”。已保存过的视频仍可再次主动选择，确认文案明确提醒，防止把上次修正又旋转一次。
- 批量默认处理可唯一确定的服务器主文件。无法确定多版本主文件时跳过并记录原因，播放器选择准确版本后仍可单独保存。
- 备份与任务记录持续保留。总空间会随已处理文件累积，空间不足时暂停队列，不删除用户备份。

## 性能与一致性

- 手机只收发 ID、标题、方向、状态；不传输视频。直接复用当前懒加载网格与封面缓存，不另行预读整库，不为选择操作创建播放器。未显示条目不会因进入选择而开始新的封面任务。
- 所有单文件和批量子任务复用现有单消费者媒体处理器；批量调度器同一时间只派发一个子任务。仍执行原片完整备份、全量校验、权限检查及同目录安全发布。
- 服务端持久化父队列和每条子任务请求 ID；先写日志再提交。服务器重启、提交响应丢失时优先查找原有子任务，包括原文件已替换的场景，不重新套用旋转角度。当前文件若在提交前中断，保留原文件并记录失败，之后可单独重试；不承诺文件拷贝断点续传。
- 暂停与取消仅控制后续派发，当前文件会完成；取消响应丢失的已接收任务仍追踪它的结果。失败可重试，成功不重复；待核对禁止当作普通失败重试。
- 每页批量获取状态，单个单元格持有独立可观察记录，只有值变化才更新。前台页面轮询，后台停止客户端刷新；服务器继续执行。
- 预览使用保存后内容 SHA-256 构造修订 URL。服务器按实际文件版本缓存 JPEG，最多一条解码任务、30 秒超时、最多 1,000 张／256 MiB 缓存；客户端最多两条未缓存预览请求，取消离屏的排队任务，并复用已有按尺寸降采样与原始图片缓存。不清空整个片库封面缓存。
- 无效日志、写入失败、权限不足、文件变化、结果不确定均不重新构造请求去覆盖原文件。客户端本地未确认提交保留原始请求，任务页自动核对同一请求。
