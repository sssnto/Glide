# Glide 1.2.0 产品规划：快速找到，放心续播

日期：2026-10-09。状态：**暂缓，保留为工程后备清单**。用户明确当前不需要这些增量，希望优先寻找吸引下载的功能和改善 App Store 搜索表达；后续产品方向以[市场调研与增长建议](Glide-Market-Research-and-Growth-Plan-2026-10-09.md)为准。尚未进入实现。分析基线：提交 `cc116c0`，本地开发版本 **1.1.0（3）**。本稿不代表 App Store 或 TestFlight 的当前版本。

## 1. 当前项目判断

Glide 已形成清楚的产品方向：**Jellyfin 私人片库 + 家庭目录刷看**，WebDAV 是补充来源。它的差异化在于按目录范围连续浏览个人视频，同时保留电影详情、节目选集和续播流程。

当前已经具备：

- 原生 AVPlayer 播放、自动兼容恢复、HDR 协商与输出检查、倍速缓冲、定位、旋转、缩放、锁定、字幕与音轨、画中画和 AirPlay 入口。
- 电影／节目海报与详情、人员作品、类型／标签、相似作品、当前范围搜索与分页。
- 常用目录规则、一轮不重复随机刷看、浏览位置恢复、节目级继续观看。
- 原文件下载、单任务队列、暂停／继续／重试、完成校验、离线海报、移除来源保留已完成下载。

这些属于现有能力，不能再次作为 1.2 的新增交付。Pro 源文件保留在仓库，但未进入当前应用构建目标，收费继续延期。

架构规模适合增量开发：`Core` 负责可测试的规则，`Services` 负责媒体／网络／缓存／下载，SwiftUI 页面承载交互。主要耦合集中于 `LibraryStore`（486 行）、`PlaybackController`（660 行）和目录／详情／播放器页面；优先提取新功能需要的边界，不重写播放器或全应用。

## 2. 下一版本应解决什么

| 优先级 | 现状与代码证据 | 对用户的影响 | 处理方向 |
| --- | --- | --- | --- |
| P0 | `LibraryStore.mergedResume` 已实现冲突合并，但当前仓库未见调用；`PlaybackController.open` 仍从 `resumePosition` 取本机优先位置 | 其他客户端已经看过的内容可能仍从旧位置续播 | 将进度合并接入真实详情／继续观看／播放流程 |
| P0 | `PlaybackController.report` 顺序发送会话事件，失败显示提示；没有持久重试队列；本地文件跳过上报 | 离线观看或同步失败后，本机记录不一定能补到服务器 | 持久保存待同步的观看状态，重连后有界补交 |
| P0 | 多处 UserDefaults JSON 解码失败回退空集合；下载清单读取／写入通过 `try?` 忽略错误 | 数据异常可能表现成收藏、记录或下载入口消失 | 加入版本、备份、失败可见与恢复能力 |
| P0 | 1.1.0（3）的弱网、真实倍速缓冲、后台任务等仍需实机回归 | 新功能建立在尚未量化的播放可靠性上 | 先完成当前构建验收，保持固定素材回归 |
| P1 | `catalogPage` 固定 `ParentId`；家庭搜索限定当前目录范围 | 用户先要记得内容属于哪个媒体库，才能搜索 | 增加当前 Jellyfin 来源内统一搜索 |
| P2 | 继续观看刷新逐节目读取集数，部分页面同时负责请求与呈现 | 大库与长节目刷新成本、请求取消行为需要验证 | 对新增请求统一取消／分页规则，测量后按需优化 |

上述是静态代码分析得到的风险，其中跨设备进度和数据异常尚未在本次实机复现。它们应进入验证与实施清单，而不是宣称所有用户已经遇到的故障。

## 3. 版本定位与范围

建议版本名：**1.2.0 · 快速找到，放心续播**。

用户承诺：在当前 Jellyfin 来源中快速找到作品；使用 Glide 和其他 Jellyfin 客户端观看后，能理解并恢复正确进度；离线或同步失败不丢记录。

本版包含三个工作包：

| 工作包 | 范围 | 优先级 |
| --- | --- | --- |
| A. 续播与数据可靠性 | 进度合并接线、持久待同步状态、异常恢复与旧数据迁移 | P0，发布必需 |
| B. 当前来源统一搜索 | 首页搜索入口、明确范围、分页、类型筛选、复用现有详情与播放 | P1，主要新增功能 |
| C. 发布与性能证据 | 1.1 基线复测、服务集成回归、真实素材与设备报告 | P0，发布必需 |

**照片时间线、SMB、本地导入、iCloud、Apple TV、新播放内核、收费暂不纳入 1.2。** 批量剧集下载、复杂组合筛选、智能片单可进入后续候选，不占本版必交付名额。

统一搜索比照片时间线更适合作为此次增量：它复用已有 Jellyfin 查询、分页、卡片与详情，服务现有电影／节目／家庭视频用户。照片需要新增媒体模型、日期规则、图片查看器、照片视频混合队列和内存管理，且本次没有用户需求证据。该优先级是工程与产品判断，不是已完成用户研究的结论。

## 4. 工作包 A：续播与数据可靠性

### 4.1 统一续播规则

建立一个供详情、个人页与播放器共用的进度决策入口，复用现有 `ProgressSnapshot.resolved`，避免各页面自行判断。

- 默认采用最新可信状态；本机有未提交修改且服务器状态不更新时，保留本机状态。
- 服务器有更新且可比较时，采用更新的服务器状态；时间信息缺失、时钟偏差或冲突无法确定时保留本机并提供明确的处理入口。
- “从头播放”“标为已看／未看”是显式用户操作，应有独立修订标记，不能被旧缓存或旧回调覆盖。
- 显式从头播放优先于自动续播；家庭刷看仍从头开始且不写观看历史。
- 节目聚合、正片／特别篇、跨季与首末集规则沿用 1.1；收藏继续独立保存。

优先利用详情与继续观看刷新已经取得的 UserData 合并进度。不要为了调用 `mergedResume`，给每次起播强行增加一次远端串行请求。直接播放可以使用本机已确定状态；晚到的服务器结果不能在首帧后突然跳转，必要时提示用户选择。

### 4.2 同步闭环

持久保存的是“观看状态意图”：来源、账号、媒体 ID、位置、已看状态、本机修订号、修改时间、重试状态。**不保存凭据、播放 URL、旧 PlaySessionId，也不重放过期的 Sessions/Playing 会话。**

- 首先做一个真实 Jellyfin 服务验证，确认目标服务器版本可用的读取／写入方式、完成标记与冲突行为，再锁定离线补交方案。
- App 前台、重新认证或用户点击重试时补交；不承诺后台一定及时同步。
- 每个媒体合并为最新待同步状态，避免累积每十秒一次的旧进度；成功只确认对应修订。
- 网络异常采用有上限的退避；认证失效停止重试并引导原地登录；来源移除后不再向其发送数据。
- 离线已下载影视可以产生待同步状态；保留下载但已删除来源时只保留本机记录，重新建立关联前不上传。
- 用户可看到“已保存在本机／待同步／需重新登录”，并主动重试。

### 4.3 最小必要的存储改造

提取 `PersonalLibraryRepository` 与 `ProgressSyncStore`。观看记录、收藏元数据、进度快照和待同步状态使用带 schema 的可靠持久化；低频简单偏好继续使用 UserDefaults。

第一步可采用单一原子 JSON 快照加上一份可恢复备份，暂不引入全库数据库。只有规模／性能测试证明需要索引或复杂事务时，再评估数据库。

迁移顺序：读取旧值 → 校验 → 写新快照 → 回读核对 → 启用新存储；旧数据保留到确认迁移成功。失败不能默认覆盖为空，也不能删除下载文件。下载 manifest 保持独立，但同样增加 schema、写入错误处理与损坏清单恢复。确认持久化成功后才推进会影响文件保留的操作。

验收：旧版升级后收藏／历史／目录规则无丢失；模拟损坏数据、写入失败和中断可恢复；重复同步与旧回调不覆盖新状态；从头播放和已看切换可经重启保留；两个 Jellyfin 客户端轮流观看的结果符合规则。

## 5. 工作包 B：当前来源统一搜索

### 5.1 入口与范围

保留 iPhone「片库／继续与收藏／离线／设置」四个标签。片库首页提供搜索按钮，iPad 片库提供同等入口，不增加独立第五个标签。

搜索页面明确显示当前来源名称和「全部可访问媒体库」。只查询当前 Jellyfin 账号可见范围，不跨服务器合并。现有媒体库／目录内搜索继续保留原范围，入口文案必须能区分。

WebDAV 继续使用现有目录搜索。本版不给它提供默认扫描整个 NAS 的统一搜索；照片也不进入结果。

### 5.2 第一版搜索能力

- 输入防抖，支持清空、取消、重试；切换来源、词语或类型后取消旧任务，旧响应不能覆盖新结果。
- 类型为「全部／电影／节目／家庭视频」；服务端分页加载，不为第一次显示拉取全库。
- 电影与节目使用现有海报卡片和详情；家庭视频保留原始比例预览、显示所属媒体库或可用目录信息。
- 搜索首版面向作品标题；节目结果以 Series 为入口，不展开单集。**不承诺按单集名称或人员姓名检索**，避免尚未实现的语义混入宣传。
- 展示无结果、登录失效、连接失败、后续分页失败；分页失败保留前面可用结果。
- 默认沿用服务器返回顺序，并以当前支持的目标 Jellyfin 版本验证，不自行声称智能相关性排序。
- 在线搜索缓存短时保存且按来源／账号隔离；离线可搜索已下载内容，明确标记“已下载”，不把缓存当作完整服务器片库。

### 5.3 播放语义

电影进入详情后单片播放，节目进入节目详情与选集；家庭视频搜索结果可点击播放。

若提供“播放这些结果”，队列只包含家庭视频，并与当前搜索条件一致：先收齐完整结果才允许随机一轮；顺序播放可先播放选中视频并在首帧后补齐，失败时明确队列未完成。搜索电影／节目不自动形成混合刷看队列。

实现落点：新增 `SearchQuery`／`SearchResult` 核心模型、`MediaClient.searchPage`、可取消分页状态对象和 `SourceSearchView`，复用现有卡片与详情。避免把请求状态继续堆入 `LibraryView`。

验收：两个媒体库中同名作品均可找到且可区分；未授权库不出现；超过两页无遗漏／重复；连续改词和切来源不串结果；返回保留条件与位置；现有范围搜索和常用随机刷看不回退。

## 6. 工作包 C：质量与发布

### 6.1 先收口 1.1.0（3）

按现有[文件路径与缓冲验证](Testing/Glide-1.1.0-文件路径与缓冲验证.md)完成实机复测。若存在播放阻断，先修复当前版本；是否需要 1.1.1 取决于实际发布状态和问题严重性，不预设已经上线。

1.2 沿用原生播放器和手势。不以新入口为理由改变 HDR 恢复、缓冲目标或预取策略；这些变化需要独立性能证据。

### 6.2 回归组织

当前未在仓库看到 CI 配置，UI 测试集中于一个约 1,500 行文件。先建立一条可重复执行的流程：核心测试、静态预检、iOS 编译、固定 fixture 冒烟与新服务集成用例。CI 环境有可用 macOS／Xcode runner 时再接入自动执行；不能只增加一个配置文件就声称全量回归完成。

以独立 fixture 用例验证进度写入失败／恢复、旧修订到达、认证失效、来源移除、分页取消和持久化恢复；播放器手势与离线流程沿用现有必要回归。固定素材与测试账号状态可重置，避免依赖运行顺序。

### 6.3 建议发布门槛

以下是计划目标，尚未实测：

| 场景 | 门槛 |
| --- | --- |
| 搜索与权限 | 固定多库用例结果完整；分页无重复；切来源与快速改词无旧数据污染 |
| 跨客户端续播 | 在线切换、离线后联网、从头播、已看／未看、时间缺失和同名不同来源全部通过 |
| 数据恢复 | 迁移、损坏快照、写入失败、重启和来源移除均有明确结果，不静默丢记录 |
| 真实播放 | 用户日常 iPhone、较新 iPhone 与一台 iPad；已知问题素材无不可恢复黑屏、错误颜色或串音 |
| 长播与快切 | 60 分钟观看、100 次切换无崩溃；资源占用不持续增长，退出不残留声音 |
| 下载 | 双任务排队、暂停／继续、系统任务失效、完成校验、重启及断网本地播放通过 |
| 易用性 | 至少 5 位目标用户能完成跨库查找、续播、离线观看；记录失败步骤与需要解释的地方 |
| 性能 | 同设备／网络／素材对照 1.1 基线；记录点击至首帧与搜索首屏 P50／P95，新增查询不能造成明显回退 |

首帧沿用旧规划的直放 P95 ≤3 秒、受控转码 P95 ≤8 秒作为待验证目标，每类至少 30 次且区分冷／热状态。搜索首屏先测真实服务器基线再锁定绝对门槛；不通过主观“感觉快”验收。

保持无默认分析 SDK的方式：小规模观察测试、主动反馈和脱敏诊断。性能与使用结论需注明样本数；测试版材料列出构建号、已测范围与未测限制。

## 7. 实施顺序与排期

下面按一名熟悉项目的开发者、能够获得测试设备与 Jellyfin 环境估算，**总量约 4–6 周**，不是已承诺发布日期，也不含 Apple 处理／审核时间。

| 阶段 | 估算 | 交付与退出条件 |
| --- | --- | --- |
| M0：基线与接口验证 | 2–3 个工作日 | 收口构建 3 回归；复现进度入口问题；确认服务端进度补交方案与支持版本 |
| M1：数据与续播闭环 | 5–7 个工作日 | 旧数据可迁移恢复；状态合并接线；失败、离线、重启、旧回调用例通过 |
| M2：统一搜索 | 5–7 个工作日 | 首页入口、范围、类型、分页与现有详情打通；权限／取消／返回回归通过 |
| M3：实机与候选构建 | 5–8 个工作日 | 固定素材、下载、跨客户端与用户任务验证；发布材料与实际能力一致 |

## 8. 后续候选与决策依据

- **1.3 候选：家庭照片与视频回忆。** 先观察家庭刷看是否高频、用户是否明确要求混合照片，再做日期来源、缺日期回退、混合队列和图片查看器的小原型。
- **批量离线：** 单片队列在真实后台场景稳定后，再验证“整季加入”与容量预算；不先做 HLS 打包或全格式离线。
- **智能清单／跨设备偏好：** 先确认跨客户端观看状态闭环，再讨论独立 iCloud 同步与多目录组合。
- **商业化：** 以真实用户重复使用与付费理由为依据；基础播放与兼容恢复继续免费，本版不恢复 Pro。
