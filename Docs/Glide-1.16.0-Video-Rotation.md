# Glide 1.16.0（5）：把视频方向保存回原文件

## 用户目标

将画面左转、右转 90° 或旋转 180°，控制器保持正常方向。保存后重新读取服务器原文件的播放器可以使用新的方向，无需每次旋转手机。

本阶段支持 MP4、MOV、M4V 的单视频轨文件，通过修改 ISO BMFF 的视频轨显示矩阵实现。只改变 36 字节方向信息，不重新编码或改动视频采样、音轨、字幕和其他元数据。MKV、多视频轨、无法校验的容器或变换暂不支持；无法成功预览的编码不能提交。

## 操作入口

播放设置 → 修正视频方向 → 添加或选择 WebDAV 写入目录 → 选择服务器原文件 → 预览并旋转 → 确认文件 → 备份并替换。

Jellyfin／Emby 的播放连接与 WebDAV 写入连接分开配置。账号密码在应用中输入，密码保存到设备钥匙串。知道媒体服务器的原文件名时，选中文件名必须与之相符；用户还需对照画面确认它确实是同一文件。

目录预览、选片、左右旋转不会替换原文件。开始保存时关闭当前播放会话；退出编辑器后按原进度、播放／暂停状态、音轨选择和倍速重新打开。保存后清理客户端来源缓存，并请求 Jellyfin／Emby 重新读取对应条目的资料；服务器拒绝刷新时提示用户手动刷新。刷新请求被接受不等于服务器后台扫描已经完成。已有离线副本需要重新下载。

## 保存和恢复

1. 用随机命名的小文件检查 WebDAV 的 Overwrite、锁定或目标 ETag 条件，检查后清理。
2. 读取原文件版本、下载并校验，确认支持范围读取；本机为三份文件及余量预留空间。
3. 生成仅方向矩阵变化的副本，上传到随机临时名称，再下载并逐字节摘要校验。
4. COPY 原文件到同目录的随机 `.bak`，下载并校验备份与原文件完全一致。
5. 获取经过验证的独占锁，或使用经过验证的目标版本条件；重新确认原文件未变化。
6. 先持久化恢复记录，再用受保护的 MOVE 替换，读取最终大小和方向矩阵确认结果。
7. 保留原始备份。恢复时先确认当前文件仍等于上次保存结果，再通过同一流程还原备份的完整字节；还原前也保留一份备份。

服务器返回 LOCK 成功但不实际阻止无令牌覆盖时，释放该锁并用全新的自建文件独立验证目标 ETag 条件；只有错误版本被拒绝、正确版本允许且内容校验一致，才使用版本保护。锁与版本保护均失效、备份失败或原文件变化时拒绝替换。替换请求发出后网络中断，记录为待核对，提供只读核对入口，不自动再次覆盖。备份不自动删除。

保存需要读取／上传完整视频，因此大文件耗时受网络、设备和服务器性能影响。保存时保持应用打开。此实现是文件内的方向元数据修正，要求读取方遵守该方向信息；不将重新编码像素作为本阶段能力。

## 独立验证包

独立标识 `com.songpeng.glide.rotationqa`，名称「Glide 方向验证」。与正式 Glide 的登录和片库隔离。用户在包内填写实际目录及账号密码；仓库与导出报告不记录私人连接地址和凭据。

验证页提供原创短片验收：随机命名上传 → 旋转替换 → 原生解码尺寸检查 → 完整字节还原 → 清理仅由此次验证创建的文件。测试失败时保留诊断状态，不修改目录中的其他视频。

## 验收记录

- 核心完整回归：255 项通过，含 6 项容器／方向测试和 10 项本机 HTTP WebDAV 网络测试。
- 网络用例覆盖锁保护、无锁 ETag 条件、服务端忽略条件、原文件被其他人修改、备份空间不足、MOVE 响应丢失后的持久化核对，以及目录越界拒绝。
- 独立包在用户 iPhone 和实际 WebDAV 上 9 项通过，包括实际视频帧解码、原样还原和遗留原创素材清理；未自动修改用户既有片源。详见 `Docs/Testing/Glide-1.16.0/`。
