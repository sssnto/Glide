# Glide 1.4.0 界面与交互设计

本轮直接落实到 SwiftUI 客户端。目标是让用户先看清内容和播放状态，随后完成播放、选集与轨道调整。主色沿用 Glide 薄荷绿，背景调整为深石墨；绿色集中在播放、选中和进度。

## 页面规则

| 页面 | 第一重点 | 信息组织与操作 |
| --- | --- | --- |
| 片库 | 海报与片名 | 收起重复大标题；紧凑海报墙；年份/时长与技术摘要分行。媒体库入口、目录与家庭视频统一使用竖版 2:3 预览，家庭视频完整显示画面。进入媒体库或文件夹默认展示媒体，顶部固定“媒体／目录”切换；保留用户设置的范围、排序及固定目录规则。 |
| 详情 | 作品与播放 | 小海报、清晰片名、年份/评分/时长/分级；音轨字幕摘要与视频规格分开；底部固定播放，收藏与下载直接可达。 |
| 剧集 | 季与集数 | 季选择靠近列表；剧集行按需创建；单集详情保留续播和从头播放。 |
| 播放器 | 视频与时间线 | 上方精简标题，下方拇指操作区；倍速、音轨、字幕一触打开选择；无可切换音轨时置灰，避免空菜单；设置集中调整、连接兼容、信息诊断。 |
| 继续与收藏 | 当前进度 | 紧凑海报行、来源、集数和进度；整行播放，侧滑管理。 |
| 离线 | 文件状态与播放 | 存储摘要、状态分组、文件大小/时长；进度更新不在主线程重复解码海报。 |
| 设置与来源 | 当前任务 | 内联标题、15pt 常规正文；说明移入页脚或可展开项；连接操作保持底部可达。 |

## 字阶、触控与适配

页面标题使用动态 title2，分组 headline，影片条目 subheadline，补充信息 footnote/caption。家庭视频在常规 iPhone 宽度展示三列竖版预览，较窄窗口自动减少列数；iPad 随可用宽度增加列数。未限制系统字号；辅助字号的片库使用单列，电影海报改为横向信息行，详情底部与设置摘要按需纵排。可操作按钮至少 44pt，主播放按钮更明显。iPhone 采用底部标签；iPad 采用系统可折叠侧栏。旋转时保留导航容器，避免正在播放的页面因宽度分类变化而退出。VoiceOver 开启时播放器保持控制栏可见。搜索提交后收起键盘，滚动时也可交互式收起；封面、个人片库和固定目录使用完整触控区域。

触控尺寸参考 [Apple UI Design Tips](https://developer.apple.com/design/tips/)。列表采用稳定身份、固定图片几何尺寸和懒加载，参考 [Creating performant scrollable stacks](https://developer.apple.com/documentation/swiftui/creating-performant-scrollable-stacks/)。

## 元数据规范

片名仅作片名；年份、时长、评分、分级、类型与视频编码分别展示，不把长轨道 DisplayTitle 塞进单行摘要。语言选择页保留完整原始名称，摘要优先展示语言、编码和默认/强制状态。视频规格仅显示服务器实际返回的字段，缺失时不推断为 4K/HDR。片库分页统一请求 MediaSources，沿用缓存并避免为每张卡单独请求详情；字段依据 [Jellyfin ItemFields](https://typescript-sdk.jellyfin.org/variables/generated-client.ItemFields.html)。

播放信息区分来源规格、实际输出和观察到的网络数据，不将下载速率当作源文件码率。原画兼容条件、失败后重试、播放器切换、字幕、队列及播放诊断沿用现有实现。

## 性能改动与验证边界

- 封面加载前后保持相同比例，减少列表跳动；图片按显示尺寸与屏幕倍率请求，取消后不回写旧图片。
- 复用现有 48MB 解码缓存与网络去重；下载海报也在 actor 中经 ImageIO 降采样，不随每次进度刷新重复 UIImage(data:)。
- 播放时间线、文字字幕与实时状态拆为独立观察视图，缩小播放时钟引起的更新范围。
- 滚动锚点不再每次扫描全部媒体，浏览位置采用非 UI 观察状态；目录排序只在内容或规则变化时计算。

具体构建、截图与测试结果见 Testing/Glide-1.4.0-UI-Validation.md。代码改动不能直接证明所有真实服务器与设备已稳定达到固定帧率，仍需结合真实大库与真机手感验收。
