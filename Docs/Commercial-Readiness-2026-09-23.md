# Glide 商业化能力走查 · 2026-09-23

## 判断与边界

当前属于已有差异化的功能验证版，可继续封闭测试，尚不建议以成熟付费播放器承诺公开销售。核心短板是播放可靠性、真实设备兼容性证据、跨设备数据一致性、售后诊断和完整交易流程。

本次依据当前 Swift 源码、README、发布记录、现有测试记录及原生截图进行走查；没有重新遍历全部真机界面，没有实测所有媒体格式，也没有重新登录 App Store Connect 核查商店状态。已知 TestFlight 为 0.1.0(2)，后续本地功能和修复不等于已发布。旧 PRODUCT-PLAN.md 是规划，其中“离线未实现”等状态已经过时；其定价是待验证假设。

## 产品定位

建议首发围绕“Jellyfin 私人片库 + 任意目录沉浸刷片”，优先服务已有 Jellyfin 的 iPhone/iPad 用户。电影/节目保持详情、选集、续播；家庭视频保持目录范围、顺序/随机、滑动浏览。照片尚未实现，不能作为现有卖点。若首发定位为“NAS 通用播放器”，则 SMB、本地文件导入及更广解码能力必须前置。

Infuse 的成熟价值包含格式覆盖、字幕/音轨和跨设备体验，不只海报墙。Glide 不必首发覆盖其全部平台，但必须让自己承诺的范围足够可靠。
参考：https://firecore.com/infuse ，https://support.firecore.com/hc/en-us/articles/115000070773-iCloud-Sync

## 能力差距与交付标准

| 优先级 | 能力 | 当前证据 / 差距 | 建议交付与验收 |
|---|---|---|---|
| P0 | 播放决策 | PlaybackQuality.swift 仅粗粒度容器/编码协商；MediaClient.playback 主要解析 SupportsDirectPlay/TranscodingUrl；返回 HLS 即标记为转码，可能混淆视频复制与重新编码 | 区分直放、无损重封装、仅音频转码、视频转码；解析实际播放方式/原因、profile/level/bit depth/codec tag；不能仅凭设备支持 HEVC 推断文件兼容 |
| P0 | 保留原画的恢复 | 当前自动失败主要回退到 1080p；首帧检测已补，但不是完整解码引擎 | 优先保留视频码流，再考虑视频转码；各方案必须由真实服务端能力决定，失败有解释。保留时间、轨道和暂停状态，避免循环重试 |
| P0 | 播放状态与诊断 | 有加载、错误、无进展和首帧超时；错误信息多为通用文本 | 统一连接/准备/首帧/播放/缓冲/重试/结束状态；记录脱敏错误域、编码参数、首帧耗时、缓冲、实际路径、设备/版本；用户主动导出可预览诊断，不含 token、密码、片名或私人完整地址 |
| P0 | 真实兼容性 | 现有单元/UI 测试大量使用本地 fixture；用户真机已出现黑屏、菜单、布局问题 | 实机覆盖 H.264/HEVC Main/Main10、hvc1/hev1、MP4/MOV/MKV、常见音轨及字幕；iPhone 13 与更新设备、iPad、最低支持系统与当前系统；断网、弱网、证书错误、禁止转码、服务器重启 |
| P0 | 生命周期与性能 | AVPlayer 每次开片重新准备；未见下一片预取；队列先收齐再开刷 | 顺序队列可渐进准备，随机保证完整范围语义；受限预取下一片，不并行启动大量转码；验证前后台、来电、蓝牙断开、旋转、多次快切、长时间播放的内存/耗电 |
| P0 | 版本与回归 | 本地修复和已装构建有差异，UI 测试曾因时序不稳失败 | App 内可见版本/build；每版变更记录、已知问题、固定素材集、可重复打包；发布前核心流程必过，保留问题样本回归 |
| P1 | 字幕/音轨 | 有轨道选择；指定字幕主要请求烧录，下一集重置编号 | 默认语言/强制字幕规则，按语言/角色匹配下一集；SRT/VTT 优先直接呈现；ASS/PGS 明确本地能力与烧录代价；字体/大小/位置、时间偏移、外部字幕导入 |
| P1 | 观看与同步 | LibraryStore.resumePosition 优先本地值；无冲突时间戳；收藏为本地记录 | 服务器观看进度冲突合并、已看/未看、重新观看、跨季续播；同步失败可重试；本地历史隐藏与服务器进度重置清楚区分；iCloud 片单/偏好可后置 |
| P1 | 系统体验 | 无明确 PiP/投屏 UI；进入后台暂停；iPad 主要自适应宽度 | 画中画、AirPlay 入口与回退、音频路由/中断；iPad 分栏与多任务尺寸、键盘；播放器控件密度、长字幕、动态字体、VoiceOver、减弱动画全链路验证 |
| P1 | 片库与发现 | 海报、标签、人物、相似推荐已有；搜索分散于当前范围 | 首页继续观看/最近添加/未看，明确范围的全库搜索；组合筛选和空态、滚动恢复、播放队列查看；电影/剧集/家庭视频保持各自观看逻辑 |
| P1 | 连接与设置 | 多来源与 Keychain 已有；登录失效提示重新添加；设置较分散 | 原地重新认证/修改来源、不丢历史；地址与局域网权限诊断；蜂窝流量、缓存容量、清缓存、默认字幕/画质、帮助反馈入口 |
| P1 | 离线体验 | DownloadStore 仅默认版本 MP4/MOV/M4V；无暂停续传；完成主要依据 HTTP 响应 | 暂停/恢复/重试，Wi-Fi 限制、并发与空间预算、完整性和可播放性检查，离线元数据；文件下载成功不代表可解码；兼容转码下载需要独立验证 |
| P1 | 数据可靠性 | 历史/偏好主要 UserDefaults JSON；部分持久化失败静默忽略 | 记录/索引迁移到有版本的持久化存储；迁移失败保留数据、可恢复；大库索引、删除来源/缓存/下载一致性测试 |
| P1 | 交易与支持 | 有 Pro 设计稿，无 StoreKit 实现与权益状态机 | 一次购买优先验证；购买、取消、待批准、恢复、退款撤销、离线已购全覆盖；购买页只列已完成能力；帮助、支持渠道和故障处理时限 |
| P1 | 隐私与上架 | Keychain、隐私清单已有；ATS 全局任意加载；未见完整政策/支持入口 | 评估收窄 ATS 与自建 HTTP 兼容边界；清单与磁盘空间等实际 API 使用核对；后台下载重定向鉴权边界测试；政策、商店隐私披露、支持页、审核演示账号和素材权利 |
| P2 | 扩展 | SMB、照片、电视平台等未实现 | 根据用户需求验证后安排 SMB/本地文件、照片时间线、智能片单、Apple TV、更多来源；第三方播放内核先做格式收益、体积、功耗、维护及许可评估 |

P0 = 扩大测试前必须解决；P1 = 第一版收费产品需要完成或明确收窄承诺；P2 = 依据定位选择的竞争力扩展。

## 建议首发商业边界

免费部分保留完整基础播放、安全更新、故障恢复。Pro 的候选价值是完善的离线、智能目录片单、批量整理、跨设备偏好与高级播放设置。购买理由须通过访谈和真实试用确认，多来源本身是否足够付费尚无证据。不要把 Jellyfin 用户自己的服务器转码算作 Glide 云服务，也不要把“修复黑屏”包装为付费功能。

首发可用 StoreKit 非消耗型内购；是否引入订阅应由持续服务价值与成本决定，而非商业化形式需要。价格与旧稿中的占位数值均未验证。

正式提交按目标市场当时的规则核对，完成购买恢复、隐私披露、有效支持联系方式、完整审核访问条件。当前已有 PrivacyInfo.xcprivacy 不代表这些工作都完成。
参考：https://developer.apple.com/app-store/review/guidelines/ ，https://developer.apple.com/app-store/subscriptions/

## 分阶段实施

1. 播放与诊断：真实问题素材清单、播放决策/状态机、原画保留路径、脱敏诊断、首帧和缓冲监测。退出条件：现有可复现播放阻断全部关闭，支持范围和不能支持的情况清楚说明。
2. 日常使用：同步续播、字幕偏好、连接重登、离线恢复、PiP、iPad/无障碍、设置与存储管理。退出条件：新用户无需开发者指导能连接、观看、续播、下载并离线播放。
3. 商业闭环：StoreKit、权益、客服/隐私/审核材料、发布流水线、小范围外部测试。退出条件：交易异常全覆盖，已售能力均实装，测试版与发布版状态可追溯。
4. 根据留存与反馈扩展：先看目录刷片使用率和重复观看意愿，再决定 SMB、照片和电视端。不要同时开多个解码内核和多个平台。

暂不按页面数量推算开发周期；播放兼容性调研、素材授权、设备与服务器矩阵会影响排期。

## 建议质量门槛（目标，不是当前实测结果）

- 支持范围内的固定真实素材回归集：所有阻断问题关闭；每个不支持案例均可解释并给可用回退。
- 稳定局域网下首帧 P95 目标：直放 ≤3 秒、转码 ≤8 秒；按设备/服务端硬件分组，冷启动转码单独记录。先测基线再锁定正式 SLO。
- 30 分钟长播、连续切片 100 次、大库至少 1 万条：无崩溃、不可恢复黑屏或持续内存增长；记录能耗与卡顿占比。
- 外部测试建议先 20–50 位目标用户，持续两周；统计连接完成率、播放成功率、错误恢复率、无崩溃会话比例和支持请求，不采集私人片名/URL。样本少时同时报告分母，不能用一两个成功会话宣称 99.9%。
- 购买/恢复/退款/离线权益/重装恢复测试通过；本机历史删除、来源移除和同步冲突不误删远端媒体。
- 新用户至少 5 次观察式测试，验证首次连接和选择目录是否需要解释；Pro 购买动机有实际用户证据。
