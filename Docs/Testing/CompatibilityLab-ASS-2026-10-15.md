# 兼容内核：ASS 起播、切轨与暂停定位修订

日期：2026-10-15。固定 MobileVLCKit 3.7.3，运行时 libVLC 3.0.23。此批仍为独立 CompatibilityLab 验证，Glide 主应用保持 1.2.1（1），没有接入第三方 SDK。

## 本批修订

上一批的双音轨 ASS 需要额外定位到 2 秒才显示，不能作为起播支持。现在验证程序直接选择字幕并播放，移除额外定位步骤；适配器在画面就绪、轨道选择稳定后按当前时间回读字幕，不要求用户拖动进度。

- 选择先保留最新意图，合并 100 ms 内的快速关闭／开启，避免不可见的中间状态清空解码输入。提交后留 250 ms 给输入稳定；开启期间的轨道回退最多重试三次。
- 字幕刷新与用户定位串行：定位进行中不回读旧时间；定位完成后读取最新位置，再完成仍待处理的字幕选择。关闭或换文件会清除请求。
- 冷启动的媒体信息可能早于 start-paused 输入就绪。播放意图会保留到真正起播；用户暂停后不自动恢复。
- 暂停定位不再依赖 SDK 的事件缓存时钟。使用公开的 `VLCLibrary.instance`、`initWithLibVLCInstance:andLibrary:` 和 libVLC C API 创建带原生时钟读取的播放器；播放器仍由 SDK 持有并遵循已有后台释放流程。暂停定位会在最新请求存活时解码目标帧。
- 暂停定位不在两个采样刚接近目标时立即回调，改为五个连续采样确认，并重新提交暂停意图；R25 发现的完成后位置漂移由此纳入回归。

时钟修订有可对照的证据：R17 定位完成时，原生时钟为 **5.000 s**，SDK 缓存仍为 **6.782 s**；屏幕内原创烧录时间也显示 **00:00:05.000**，字幕同时存在。测试不能只把请求目标写回界面来宣称定位完成。

API 依据：[VLCKit 3.7.3 实现](https://github.com/videolan/vlckit/blob/3.7.3/Sources/VLCMediaPlayer.m)、[libVLC 3.x 播放器公开 API](https://videolan.videolan.me/vlc-3.0/group__libvlc__media__player.html)。新桥接没有读取 ObjC 私有字段或调用未公开选择器；它只在独立验证工程编译。

## 验证方法

复用原有 10 个原创素材和 SDK 哈希，没有修改字幕时间来绕开问题。`testASSSubtitles` 覆盖单音轨、双音轨的直接起播；`testASSSubtitleLifecycle` 冷启动双音轨文件，并保存以下七个屏幕检查点。

| 检查点 | 字幕预期 | 其他断言 |
| --- | --- | --- |
| 初次起播 | 显示 | 不调用额外的用户定位 |
| 关闭字幕 | 隐藏 | 保持暂停和原时间 |
| 暂停中开启 | 显示 | 时钟保持稳定 |
| 2× 与快速关闭／开启 | 显示 | 3 s 内输入稳定并开始推进，随后按实际耗时测得速率 1.5–2.5× |
| 连续定位 15 → 5 s | 显示 | 仅最后一次回调，保持暂停与 5 s 位置 |
| 换文件并关闭字幕 | 隐藏 | 旧选择／旧刷新不影响新文件 |
| 新文件暂停中开启 | 显示 | 新输入独立应用选择 |

屏幕截图用 Vision OCR 检查完整原创字幕 `Glide ASS subtitle` 是否出现，关闭场景要求其消失；另检查黄色粗体和黑色底框。截图阶段暂停视频，避免测试工具连接或识别期间素材播到片尾。只有实际媒体画面与屏幕文字都满足条件才计为通过。

### 审计发现与测量修订

R17 的七个状态检查曾全部通过，但不足以作为最终结论：后续 R18 全组仍在倍速字幕画面失败，R23 两次重复运行一败一过，失败原因是倍速推进断言。上次任务因此未完成。失败历史予以保留，不以单次成功覆盖。

原倍速检查在 `play` 与字幕刷新后固定等待 700 ms，就假定准备已结束，并把 `Task.sleep(1.2 s)` 当作实际耗时。这不能区分异步定位／解码准备、实际速率与测试调度延迟。本轮改为分别限时 3 s 等待播放状态／2× 速率／字幕请求稳定和真实时钟开始推进，然后记录原生时钟差与单调时钟的真实耗时。通过条件为实际推进比 1.5–2.5×；它比旧检查的上限更严格，保留字幕 OCR、暂停与用户定位的原断言。等待超时会明确失败，不能无限等待直至通过。

R24 在测试启动阶段超时，没有形成有效的功能结论。R25 两次运行一败一过，失败为暂停定位后的时钟漂移；增加稳定采样与暂停意图确认后，R26 的七个检查点通过，R27 整组中的同一生命周期用例再次通过。R27 其余四个格式／控制／退出用例通过；直接起播字幕用例失败于暂停后请求解码 PNG 未产生，尚未进入 OCR。解码截图请求需要后续输出帧，因此改在播放时完成，随后仍暂停做独立屏幕 OCR；没有移除任何图像、文字或显隐断言。

最终代码 R28 **6 个独立界面用例全部通过，0 失败／跳过**，不是累加中间轮次得到的数量。

## 支持边界与下一步

这是同一组 320×180／15 fps 原创长字幕样例的模拟器结果，不代表复杂 ASS 特效、附件字体、图形字幕、外挂字幕、4K／HDR 或所有字幕布局均已支持。音轨切换仍只验证索引，尚无真实声道听测。本轮没有重新宣称主应用核心测试或真机功能已经新增。

进入 1.3 本地兼容播放接入前，继续冻结分发构建材料，并补真机的字幕、暂停定位、内存、后台与系统输出回归。WebDAV 增强继续暂缓。前一批证据与体积材料见 [独立内核验证](CompatibilityLab-2026-10-15.md)。
