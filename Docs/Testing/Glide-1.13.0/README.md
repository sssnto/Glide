# Glide 1.13.0（1）：统一片库

2026-10-26。按已确认范围完成跨来源搜索、可靠标识聚合、来源／版本选择与记忆，以及频道和离线行程入口。核心 **227 项**、最终模拟器 **5 条流程**和最终 iPhone **25 项生产链路检查**通过；Release 归档、签名及 dSYM 校验通过。尚未提交、推送、打标签或上传商店，官网仍对应已发布的 1.11.0。

## 已实现

- 首页「搜索全部片库」、片库更多菜单和影视片库搜索入口进入统一搜索，保留原目录浏览与底部导航。支持 Jellyfin／Emby、本地授权视频和已完成下载；类型与来源可筛选。
- 每个远程来源独立请求、分页和超时，已返回结果先显示；旧查询取消后不能覆盖新结果。没有关键词时先浏览已索引资料，输入关键词再查询媒体服务器；本地只做授权目录的文件枚举。
- 同类型、有效且一致的 TMDB／TVDB／IMDb 标识聚合。优先级为 TMDB、TVDB、IMDb，不猜测跨提供方关联；同名无 ID 各自保留，标识冲突时拆开。媒体版本及离线副本仍是不同播放入口。
- 作品页刷新来源版本，展示实际获得的分辨率、编码、HDR、封装、大小与本机状态。保存所选入口；已选版本被移除后要求明确重选，不能静默改播。来源／账号／地址或作品标识变化时重新核验。
- 下载文件只可复用其对应媒体版本。用户明确选择 v2 时，已有的 v1 下载不会覆盖它；播放仍沿用生产 PlaybackController、内核、字幕和音轨能力。
- 搜索结果复用现有频道和离线行程，节目可进入季集页。频道使用所选来源的默认版本，离线行程只支持默认原文件，界面说明并再次确认预算；不把不同剪辑版本的时间直接互套。
- 搜索缓存与账号／地址绑定，只持久保存受限显示元数据和稳定身份，清除播放 URL、图片 URL、服务器 Path、字体附件及认证信息。缓存与匹配在主线程外处理，最多保留 10000 条；本地限 500 个目录／5000 个文件，原生 List 分批展示。

## 真机状态与隔离

测试仅使用项目原创动态视频及自建 Jellyfin／Emby 合约服务，没有读取私人服务器媒体或正式 Glide 的登录。索引、媒体库快照、频道和下载均使用独立 QA 目录；固定测试源 ID 不覆盖真实来源，播放检查不写观看进度。真实媒体服务器与用户片源的全面矩阵仍需用户后续体验，本轮不据合约测试宣称已覆盖所有服务端版本、代理和编码。

手机解锁后最终 25 项已通过并成功读取报告。随后设备控制连接超时，自动退出测试模式回到正常首页未完成，见 [恢复尝试](Logs/iPhone-Restore-Normal.log)。这不改写已经完成的真机结果；用户可从多任务划掉「Glide NAS 验证」再点击图标打开，进入正常首页，通过「搜索全部片库」使用已有或自行添加的来源。无需重装。正式 Glide 未被独立验证包替换。

## 过程记录与边界

首次测试中，原创服务漏处理 `MediaTypes=Video` 的剧集递归查询，导致行程候选为空；修正后生产检查与 UI 均通过。[首次日志](Logs/UI-First.log)、[修正后日志](Logs/UI-Second.log)保留。组合回归随后发现旧用例假设按钮已在视口内、旧行程过多导致新行程不易找到，以及部分入口触控区域不完整；补齐可见性处理、整行点击区域和新行程优先排序。验证本身也在每轮清理自己的副本／缓存，避免前一轮离线样例改变初始结果数。失败记录见 [组合回归历史](Logs/UI-Regression-Before-Visibility-Fix.log)，最终五条断言没有跳过。

元数据可能过期，缓存存在不等于来源在线，页面给出说明与更新时间；播放前再次核验，但不把元数据校验描述为完整文件哈希或整片解码。没有全 NAS 索引、自动刮削、新增 Plex／飞牛或跨设备进度同步。当前仅支持按优先提供方的有效 ID 保守聚合，不做不同 ID 提供方之间的跨表匹配或片名模糊合并。

不把本次 HTTP 冻结验证写成用户操作飞行模式；1.12.0 的用户飞行模式确认仍属于其历史记录。真实 NAS、真实服务器压力、后台下载与全编码矩阵不由本次原创样例替代。未记录 iPhone 大片库的滚动 FPS，不能仅凭核心 10000 条搜索测试宣称滚动性能达标。
