# Glide 1.9.0（6）：Jellyfin 默认字幕

2026-10-22，在用户 iPhone 13 Pro Max（iOS 27.0）主应用中复现并修复指定剧集默认字幕不显示的问题。修复包已安装，完成检查后已退出诊断并恢复普通片库页面。

## 原因与修复

服务器返回一个默认 SubRip 轨道，未标注语言。PlaybackInfo 的 `DefaultSubtitleStreamIndex` 为 2，视频播放地址却没有 `SubtitleStreamIndex`。原实现只从显式选择或视频地址取得编号，因此没有读取单独传输的默认字幕；原生 HLS 流也没有字幕轨道。基线报告中服务器字幕数为 1，客户端字幕数为 0，字幕偏好和该片记忆均未设置为关闭。

客户端现读取所选媒体版本的协商默认编号，顺序为手动选择、视频地址、协商默认值，并验证编号属于该版本的字幕清单。显式关闭、服务器关闭、无默认值、强制字幕过滤及不同版本的编号不互相替代。不凭文件 `IsDefault` 标记强行开启字幕。直连和 HLS 路径均在视频装载前安装可读取的字幕；需要单独字幕的影片不缓存缺少字幕的预加载资源。

此契约与 [Jellyfin MediaInfoHelper.SetDeviceSpecificSubtitleInfo](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Api/Helpers/MediaInfoHelper.cs) 的默认编号、External 字幕交付字段一致。实际服务器行为以本轮脱敏报告为准。

## 真实设备结果

修复后自动加载轨道 #2 的 870 条字幕。定位到 16.185 秒时，实体机预览中可见生产共用字幕组件显示的英文对白；截图仅保存在本机临时目录，未纳入仓库。此轨道共 870 条含文字字幕、0 条中文，服务器当时没有返回第二条中文字幕，不能将默认显示修复描述为新增了中文字幕。

两轮完整生产控制器检查均通过 8 项：自动加载、暂停时钟、暂停定位、实际时间存在字幕、关闭字幕且保持视频会话、重新开启并保持会话／时间／暂停状态、继续播放、退出重进恢复字幕选择。最终报告确认检查后恢复了原有两路字幕记忆，播放检查使用 `recordsProgress: false`，未上报观看进度。

最初诊断曾额外要求中文对白，因原轨道为英文而停止；更正诊断条件后通过。一次视觉复核被切换至 NAS 应用打断，不作为验收通过证据；用户返回 Glide 后重新完成前台检查。初次预览未看到文字，最终已在实体机屏幕确认显示，没有只以字幕数据存在代替视觉结论。
