# HLS 清单播放故障验证

日期：2026-09-30。当前工程版本：1.0.2 (1)，未更改版本号。

## 故障证据

用户诊断显示：原始媒体为 3840×2160 HEVC Main 10；自动播放、1080p 和 720p 均在首帧前失败，错误码相同，为 -12927。服务器有两个相近名称的剧集版本；与诊断匹配的是《海贼王(真人版)》第一集「起点与终点」，元数据为 Dolby Vision Profile 8 / HDR10。

读取真实 1080p / 720p 转码首分片，实际编码为 H.264 High / 8 bit，音频为 AAC。总清单却声明 SDR / AVC Baseline，分片仍含 PQ / BT.2020 色彩标记。服务器色调映射处于关闭状态，本次仅做只读检查，未改变服务器全局配置。

Apple AVPlayer 的对照实验结果：同一 HLS 总清单报 `CoreMediaErrorDomain -12927`；直接播放该清单指向的媒体清单能解码出帧。同一短分片转存为 MP4 也能出帧。因此，失败位于 HLS 总清单描述与实际流的兼容环节，继续降低分辨率不能解决。本记录不把 -12927 概括为所有 HEVC / Dolby Vision 都不受支持。

[Apple HLS 编写规范](https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices/)与[4K/HDR HLS 说明](https://developer.apple.com/videos/play/tech-talks/501/)说明了 CODECS 和 VIDEO-RANGE 对播放器选择兼容流的作用。

## 修复范围

- 在 Jellyfin 原生播放路径中读取总清单。只有单条、音视频合并的 AVC 流可直接使用媒体清单，让 AVPlayer 根据实际流解码。
- 多画质、独立音轨／字幕、会话密钥、变量／流引导以及 HDR/HEVC 总清单保留完整结构。解析失败仍走既有 AVPlayer 处理。
- 保留当前播放会话、服务器轨道选择、续播、手势和缓存进度。不会通过切换播放器内核处理故障。
- 诊断升级至 schema 3，保留 CoreMedia 原始错误域及有限的底层错误链；区分服务器原始媒体参数与播放器读取的输出编码、色彩标记。不导出 URL、密码、令牌或错误文本。

## 已验证

| 验证 | 结果与范围 |
| --- | --- |
| 指定真实视频的 Apple 原生解码 | 总清单可复现 -12927；媒体清单在自动播放、1080p、720p 路径均可出帧。这是 Mac 上的 AVPlayer 解码探针，不能替代 iPhone 实机验证。 |
| 核心回归 | 55 项通过，覆盖单路清单、反向代理路径、认证查询保留、多画质与独立轨道保留、HDR/HEVC 清单保留、跨来源拒绝和诊断隐私。 |
| iOS 模拟器应用内播放 | 错误清单测试服务仅一次协商便出画面；导出诊断含 `hls_single_variant`，无 `item_failed`。 |
| iOS 模拟器交互 | 合并进度条拖动与缓存显示、控制台自动隐藏后短点唤出通过；共 3 项 UI 测试通过。 |
| iOS 构建 | Debug 模拟器、Release arm64 设备构建通过；Release 为不签名编译验证，未安装到用户 iPhone。 |

自动 UI 验证启动测试服务时设置 `GLIDE_HLS_MASTER_FIXTURE=1`，执行 `testAutomaticPlaybackRecovery`，并在测试 runner 中传入同名环境变量。测试视频来自应用自带演示，未写入私人视频或账号。

## 实机复测

使用新代码在 iPhone 上重新构建运行，播放上述视频，确认有声音和画面；拖到未缓存位置、暂停后拖动、切换可用声音和字幕，再退出并续播。至少补测一部普通 SDR 电影和一部已能正常播放的 HDR/HEVC 视频。

首次服务端转码和网络下载仍需时间；本修复保证不因已确认的清单兼容问题反复失败，不承诺固定秒数起播。若仍失败，请导出 schema 3 诊断，核对 `errorDomain`、`errorChain`、`playlistMode` 与 `outputVideoCodec`。
