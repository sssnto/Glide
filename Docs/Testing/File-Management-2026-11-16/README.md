## 环境及边界

API 测试仅访问本机 `127.0.0.1:8840` 的官方 `jellyfin/jellyfin:12.2` 容器，内存上限 768 MiB；媒体均为仓库原创 12 秒样例副本。最终检查后已停止该容器，保留测试数据。没有连接用户 NAS 执行移动、删除或还原。本轮未测不同 NAS 文件系统的全部行为，也没有做跨卷复制。

服务端源码提交：`ad1685a85a628251949f4bcb64a19075acdf50e4`；公开清单登记提交：`dd69ca1`。Linux 自动构建与发布均通过。公开安装包 SHA-256：`83ee4011b1104ae0989ea411e370090b6d683719e38b277a5c2a99239eb2da1b`。

本地详细构建与测试日志保留在忽略的 `.build/FileActions-*` 中。设备标识、账号凭据和安装诊断不进入公开验收记录。

## NAS 验收步骤

1. 等现有旋转任务结束，从原插件存储库更新 Glide Toolkit 到 1.2.0.0，重启 Jellyfin。
2. 管理员在插件设置单独开启“家庭视频文件整理”。普通用户另填允许整理的用户 ID；媒体卷需可写。
3. 在独立「Glide 兼容验证」2.0.0（2）打开家庭视频目录，用几份可整理的副本验收。在原网格点“选择”，勾选后移动，检查目标目录与外挂字幕。
4. 进入“任务 → 文件整理”检查完成数量、逐项结果，并还原到原目录。再验证删除及还原。不要用仅有的一份重要媒体进行首次验收。
5. 删除采用可恢复回收目录，不释放视频占用的 NAS 空间。需要保留 `.glide-trash` 和插件任务记录，才能按记录还原。

独立验证包已安装到已配对 iPhone，主应用未覆盖。最后启动被 iOS 锁屏拦截，解锁后可手动打开；NAS 新功能验收仍待上述插件更新和权限开启。
