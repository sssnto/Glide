# Jellyfin 旋转事故修复 · Glide 1.16.0（11）／插件 1.0.1

## 事故与原片恢复

用户 NAS 在插件 1.0.0 保存后留下完整大小的 `.bak` 和 `.part`，服务器任务在提交阶段进入 `uncertain_commit`；Jellyfin 随后报告原路径不存在，并从片库移除条目。旧日志没有保留具体 IO 错误，不能据此确定 NAS 内核或挂载层的具体故障。原问题定位于提交替换阶段，而非播放解码。用户复制 `.bak` 回原目录并恢复原文件名，已确认可以播放。

手机只读复核也已通过：Jellyfin 12.2.0 重新返回该媒体条目、原文件 Range 读取 206／4 KiB 和 MP4 头，PlaybackInfo 返回 200。原服务器仍为插件 1.0.0，旧任务处于等待核对；没有向该 NAS 提交新的旋转、覆盖或删除请求。报告仅保留技术摘要，不记录私人片名、目录、地址、令牌或任务身份。

## 修复内容

- 改用 Linux `renameat2(RENAME_EXCHANGE)`，先在实际原片父目录与工作目录之间用随机小文件测试交换和禁止覆盖语义。失败在接触视频前拒绝，不调用覆盖复制回退。发布后校验两边的完整摘要。
- 备份同时保留所有者、模式及可读取的扩展属性，并同步到磁盘。正常保存后 `.part` 是交换出的前一版本；旧事故中的 `.part` 是未提交的输出，不能把两者混为一谈。
- 管理员恢复页独立于媒体条目，通过服务器记录与 SHA-256 补回缺失原片；已有其他文件时拒绝覆盖。保留 `.bak`、`.part`；视频已经手动恢复时只核对并结束异常状态。停用正常旋转仍可使用管理员恢复。
- 服务端保留具体失败代码，不把 IO 路径或凭据写到插件诊断日志。Glide 先读取已知任务，再检查当前文件能力，保留不确定请求身份；包括断线重试在内的所有新提交都拒绝旧插件 1.0.0。
- 安装包包含 DLL、meta.json、SHA256SUMS、安装说明和停止容器后更新的脚本。官方容器确认实际显示版本 1.0.1.0，并提供新版恢复设置页。

大文件来自项目原创短片加合法 `free` 盒，总长 536,929,239 字节；控制请求正文 258 字节。它验证服务器 IO 和事务流程，不代表真实长片解码、用户 NAS 或手机网络流量测试。该轮大文件、两个任务的备份和交换文件已按精确名称清理；历史记录保留，临时服务已停止。

Release 有既有 WebDAVPlaybackBridge 捕获诊断和 AppIntents 无依赖提示，不属于本次改动；未将构建表述为零警告。插件 Release 为零警告、零错误。

## 升级与剩余验收

按 [插件安装说明](../../../../Server/README.md)停止 Jellyfin 容器，将修复包 DLL 与 meta.json 替换进**原有插件目录**，再启动，确认显示 **1.0.1.0**。保留媒体备份、插件配置和数据目录内的任务记录，不额外放置可被加载的旧版 DLL。

首次只用可覆盖的测试副本，保存后重新播放并还原；目录安全检测失败时保留原片和错误编号，不绕过。真实 NAS 新版保存验收仍未完成。本轮未提交或推送 Git，未上传商店。
