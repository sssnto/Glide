## 服务器验收

- 官方 `jellyfin/jellyfin:12.2` Linux ARM64 容器实际加载托管插件，API 通过 Jellyfin 登录认证；不是替代服务模拟。
- **20 项真实服务检查通过**：插件加载、格式边界、服务器方向实际变化、ffprobe 确认顺时针 90° 组合与完整备份、权限保持、其他文件不改变、幂等请求不重复旋转、同 ID 不同内容拒绝、过期版本拒绝、错误媒体版本拒绝、普通用户默认无写权限及不可查询写任务、显式授权接受 compact 用户 ID、核对接口只读、原样恢复、重连查询、结果不含路径／凭据、正在播放期间不替换、停止播放后处理并可原样还原。见 [API 报告](Server-API.json)。
- **512 MiB 大文件的五项检查通过**：仅在服务器处理；控制请求正文 **258 字节**；服务器返回接受响应头后客户端在读取 JSON 响应体前断开，任务继续完成；实际重启 Jellyfin 容器后任务和备份保留，相同请求不重复旋转；完整 SHA-256 原样还原。实际文件长度 **536,929,239 字节**，来自仓库原创 MP4 加合法 `free` 容器盒，不包含私人片源。见 [大文件报告](Large-File-Restart.json)。这是本地脚本模拟断线及真实 Linux 服务处理，不是手机网络流量测量。
- **16 项服务器文件核心检查通过**，包括矩阵外所有字节一致、大小不变、备份精确、还原前备份、版本变化拒绝、替换前中断不改原片、重启后识别已提交结果、不确定结果只读且阻止重复、目录越界／符号链接拒绝和取消不改原片。核心程序运行于 macOS；Linux 文件同步、权限和替换则由上述官方容器 API 实测。见 [核心报告](Server-Core.json)。
- 服务端固定使用 .NET 10、Jellyfin.Controller／Model 12.2.0，Release 构建零错误、零警告。服务器内部路径只保存在本地事务日志，API、测试报告不导出路径和认证信息。

首轮开发发现 Linux ARM64 与 x64 的 `O_DIRECTORY` 常量不同，已改成两者通用的只读目录句柄，并实测 fsync；未通过的初始 POST 不计为最终通过。首次测试文件名包含 `Sample` 被 Jellyfin 官方解析器忽略，改用原创测试专名后才得到真实索引媒体。第一次断线测试在服务确认接收前关闭连接，没有入队；最终用接受响应头后断开来验证后台任务，不把“未送达的请求”当成已接受任务。

## 客户端验收

- 完整核心回归 **Swift Testing 273 项、21 个套件及 XCTest 七项通过**，HTTP 旋转测试已开启；新增当前在线 Jellyfin 媒体版本绑定、离线／Emby 拒绝、无路径凭据的持久请求、任务状态边界。见 `Core.log`。
- 管理员实际从播放器进入方向操作、预览、确认服务器原文件、保存后显示画面并从备份还原；普通账号不能保存；既有 WebDAV 旋转／精确还原／目录封面和缩放几何回归。最终逐项结果、构建与手机安装状态以 `Validation.json` 为准。
- 自动化首轮出现原创验证入口首次布局变化导致点击没有打开播放器；失败时仍停在验证入口，未进入生产播放器或提交服务器任务。保留失败日志，最终用稳定布局并确认播放器出现后才继续检查，不能把失败尝试计为通过。

## 使用边界

第一版仅对 MP4／MOV／M4V 单视频轨修改显示矩阵，不做像素转码。NAS 必须能读写本地媒体与父目录，并能保留文件所有权／权限／扩展属性；不支持的文件或文件系统在替换前拒绝。目录余量至少覆盖备份和临时文件，历史备份另外占空间。

每个原文件最多一个活动或待核对任务，队列串行执行；其他设备播放期间等待，超时拒绝。服务器替换前重启会标记中断并保留原文件；替换附近重启只读核对，不自动重复旋转。不宣称对不遵守锁的外部编辑工具提供文件系统级 CAS，需避免其他程序同时编辑同一原片。

备份与日志默认不自动删除。用户安装插件并确认后，还需要真实 NAS 的能力检查与可覆盖副本保存／还原验证。本轮没有提交、推送、打 tag、上传商店或改动用户原有视频。

最终客户端 **1.16.0（10）** 已安装到主应用，自动启动被锁屏拒绝，未将其计为真实 NAS 验收。最终 Release 构建、深度签名和静态预检通过。管理员保存／还原、普通用户限制、既有 WebDAV 与缩放四项 UI 分别通过；中间组合运行中测试入口点击未生效的失败不计为通过，详见各日志。
