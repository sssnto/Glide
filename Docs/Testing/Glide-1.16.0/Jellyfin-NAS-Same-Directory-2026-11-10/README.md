# NAS 同目录原子保存 · 插件 1.0.2／Glide 1.16.0（11）

> 历史方案：1.0.2 随后在实际 NAS 返回 atomic_rename_13，测试短片原路径缺失。确认媒体卷为 SMB2，修复原文件读取句柄跨越提交的问题后改用 1.0.3；参阅 [SMB 句柄修复](../Jellyfin-SMB-Handles-2026-11-10/README.md)。不要继续使用此版处理原片。

## 实际 NAS 发现

用户已安装 1.0.1，手机应用内确认插件版本、原片 Range 读取及 PlaybackInfo 正常；旧事故任务已在重启时只读核对为失败状态，不再等待确认。初次上传原创测试短片的 WebDAV 目录未加入 Jellyfin 片库，不能把搜索不到当作播放或插件失败。当前保存账号管理接口返回 403，不能代替管理员刷新；用户已把短片复制到已入库的原片父目录并刷新。

随后在实际 NAS 上找到这一新 UUID 命名短片，下载 58,319 字节并与项目原创素材逐字节核对一致。1.0.1 在小文件探测阶段返回 `atomic_exchange_22`（EINVAL），任务失败，未进入备份或视频替换。见 NAS-1.0.1-Probe-Refusal.json。该结果证明该 NAS 拒绝了交换操作，不足以证明 1.0.0 原片缺失的具体底层原因；不能将安全拒绝表述为 NAS 保存通过。

## 1.0.2 改动

- 优先使用已验证的交换；不适用时，独立探测原视频同一父目录内的原生 POSIX rename。
- 同目录模式输出暂存为原片父目录的 UUID 隐藏 `.part`，原始完整 `.bak` 仍在 `.glide-rotation`。只调用原生 rename；跨目录直接拒绝，EXDEV 等失败不调用复制或先删除目的文件的回退。
- 提交前同步原文件父目录、备份及暂存文件，记录发布方式，复核原文件版本、完整摘要及播放占用；提交后核对输出完整摘要。同目录成功后暂存名字被消耗；交换模式保留交换出的前一版本。
- 服务器任务新增 publicationMode 字段，客户端可选解码，旧响应仍兼容；服务器内部路径不进入 API 或脱敏报告。
- 索引后的真实 NAS 测试只复用已复制的 UUID 短片，先检查父目录、文件名及完整原始字节，再提交服务器处理。不会旋转或删除此前恢复的私人原视频。

共享挂载实际选择 SameDirectoryRename，原生 Linux 目录选择 Exchange。大文件 536,929,239 字节，来自项目原创短片加合法 free 盒；命令正文 258 字节，不经手机传输大文件。这是本地真实官方容器测试，不是用户 NAS 大文件验收。测试通过后仅清理本轮精确命名的大文件和备份，历史记录保留。

第三方程序仍应避免并行编辑同一原片；版本和摘要复核不等于针对任意不遵守锁的写入程序提供 CAS。缺失原文件的补回仍要求不覆盖发布语义；底层不支持时保留备份并使用 NAS 文件管理器复制恢复，不降级为盲目覆盖。

## 用户升级与后续

按 [安装说明](../../../../Server/README.md)停止 Jellyfin 容器，将 **1.0.2 包内的 DLL 和 meta.json** 替换到原有插件目录，再启动并确认显示 **1.0.2.0**。保留现有配置、任务记录、`.bak` 及 `.part`。手机已保留连接和原创测试入口，之前复制、刷新的短片可以继续用，无需再复制或登录。
