# SMB2 提交句柄修复 · 插件 1.0.3／Glide 1.16.0（11）

## 已确认的缺陷

用户 NAS 1.0.2 日志为 `atomic_rename_13`，之后测试短片原路径缺失；用户截图确认 57 KB 暂存及备份仍在，恢复后的 691.7 MB 私人原片仍在。容器只读诊断确认文件系统为 **smb2**、目录及测试备份显示 uid/gid 1000、模式 755。终端 id 为 root，不据此推断 Jellyfin 主进程身份；ps 在该容器不可用。

旧处理器的 `await using original` 持有共享读取句柄直至 Execute 结束，跨越了原文件发布。小文件探测却在 rename 前关闭文件，因此没有覆盖这个差异。新增提交钩子检查在修复前稳定失败，提示目标仍被占用；提前 DisposeAsync 后通过。见 Core-Before-Fix.log 和 Server-Core.json。

[Linux flock 文档](https://man7.org/linux/man-pages/man2/flock.2.html)说明 SMB/CIFS 可能采用强制锁，从另一描述符进行 IO 会收到 EACCES，具体行为依协议、内核、挂载选项和服务器而异。[.NET Unix 文件实现](https://github.com/dotnet/runtime/blob/release/10.0/src/libraries/System.Private.CoreLib/src/Microsoft/Win32/SafeHandles/SafeFileHandle.Unix.cs)显示 FileShare 会参与 flock，且普通文件访问会忽略部分锁错误；写入模式的 SMB/NFS 描述符会跳过自动共享锁。

## 修复

- 输入校验后先检查原片读写访问和独占锁，失败时不创建备份或进入发布。
- 完成内容校验后显式关闭原片读取流；版本及完整摘要复核所用的临时读取也在提交前结束。
- 以读写共享模式打开检查描述符，再执行一次原生独占 flock 并要求成功。随后显式解锁、关闭描述符，才进行同目录原生 rename 或交换；不在 rename 时持有自建锁。
- 不使用 .NET 自动独占锁再重复申请相同 SMB 锁；该中间实现也在隔离共享测试中触发 EACCES，最终单次锁检查已通过。
- 原片有外部读锁时，在备份与替换前拒绝；不改 NAS 权限、不放宽媒体目录限制、不回退到覆盖复制。
- 任务响应补充可选 failureCode，仅包含已有技术代码，不含路径或凭据。客户端最低安全插件版本改为 1.0.3。

## 实际 SMB2 前后对比

测试基于官方 Jellyfin 12.2 镜像，在独立容器内安装 Samba 4.22.11／cifs-utils。Samba 仅监听容器回环地址，使用虚构测试账号；内核 CIFS 挂载通过 stat 确认为 smb2，uid/gid 1000、755。媒体仅为项目原创短片及合法 free 盒扩展，不访问实际 NAS 或私人账号。临时 SYS_ADMIN 权限只用于该容器挂载，结束后移除整个容器。

1. 同一共享上运行 1.0.2，复现提交失败且原路径消失，局部错误为 atomic_rename_2；真实 NAS 为 atomic_rename_13。错误编号不完全相同，不将本地环境冒充用户 NAS。Before.json 的 passed 表示成功复现预期失败，不表示旧版可用。
2. 同一共享更新 1.0.3，旋转、方向变化、幂等、完整备份及逐字节还原通过，旁侧原创文件不变。
3. 加入真实外部 SMB 读锁，任务在进度 0、未生成备份时拒绝，原始摘要不变。最终 **12 项 SMB 检查通过**。
4. 在 SMB2 上使用 536,929,239 字节的原创容器文件验证：命令正文 258 字节、客户端断开后处理继续、实际重启容器并重新挂载、同请求不重复旋转、完整 SHA-256 还原。**5 项大文件检查通过**，测试通过后清理本轮精确命名的大文件和备份。

另有 50 项文件核心与故障注入、22 项普通目录恢复、20 项协议／权限／播放占用、5 项 Swift 数据与版本保护回归。最终构建、签名及数量以 Validation.json 为准。

## 实际 NAS 剩余步骤

用户 NAS 目前已确认的版本为 1.0.2，已入库测试短片的原路径消失，不能直接再次运行；私人原片没有参与后续测试。先停止 Jellyfin 容器，在停止期间从未入库目录复制原来的 57 KB 原创 UUID 短片回同一测试位置、同一文件名；按 [安装说明](../../../../Server/README.md)替换 **1.0.3 的 DLL 与 meta.json** 后启动。启动恢复可只读核对已补回原片的旧任务，再刷新对应媒体库。保留所有现有备份和暂存文件。

客户端最终保护已更新，连接及登录保留。实际 NAS 上的 1.0.3 保存／原样还原仍待此次升级后验证，未提前标记通过。历史 1.0.0–1.0.2 安装包仅作为历史留存，不再推荐部署；本轮未提交或推送 Git、未上传商店。
