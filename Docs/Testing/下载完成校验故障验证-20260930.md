# 下载完成校验故障验证

用户反馈：下载进度走完后变成「下载失败」，错误为 `Cannot Open`。

同一段本地 MP4 演示视频的原生复现结果：把文件命名为无扩展名 UUID 后，AVFoundation 返回 `AVFoundationErrorDomain -11828 / Cannot Open`；保留 `.mp4` 后，`isPlayable` 为 true，并能读取到 1 条视频轨。

原因是下载回调为了保留 URLSession 的临时文件，把它移动到了一个没有扩展名的新文件，再交给 AVFoundation 校验。另一个状态问题是下载网络任务已经结束后，列表刷新会把异步「校验中」误判为「已中断」。

修复后，下载回调同步将文件暂存到 Application Support 的 Pending 目录，并保留 MP4／MOV／M4V 扩展名。文件大小与系统可播放性校验通过后，再移到正式离线目录并保存「已完成」状态。校验中的任务有独立登记；重启时可恢复暂存文件，重复回调不再重复处理已经发布或拒绝的文件。重试采用新的任务文件标识，避免旧进度／失败回调覆盖新任务，成功时清除旧提示。后台事件完成前等待文件校验与状态保存。

验证：58 项核心测试通过，包含真实 MP4 暂存、恢复、原生打开、发布与删除，以及错误网页和不完整文件的拒绝检查。Debug 模拟器编译通过，iOS arm64 Release 未签名编译通过。

端到端测试 `testOfflineDownloadIntegrityRetryAndRestart` 使用仅含演示视频的本机服务：第一次响应只包含半个文件，应提示文件不完整；重试收到完整文件后进入「已完成」。进出下载页、重启应用后仍可离线播放并显示首帧；总下载请求保持 2 次，播放不请求远程视频流。移除测试来源后，离线记录与文件随之移除。最终代码回归结果为 1 项通过、0 项失败、0 项跳过。
