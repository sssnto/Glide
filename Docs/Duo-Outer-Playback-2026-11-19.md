# Duo 外屏播放画面修复 · 2.0.1（12）

用户反馈：Duo 外屏竖屏观看存在遮挡，横屏后视频比例异常。使用官方 iOS 27.1 Duo 模拟器、独立演示应用和原创素材复现；未连接用户媒体服务器。

## 根因

1. `VideoSurface` 将完整视频按比例绘制到全屏区域，但 `AdaptivePlayerLayout` 对外层安全区域大小的容器执行了 `clipped()`。渲染层与裁剪层边界不一致，导致画面右侧或底部被截断。修复前的横屏回归测得约 7.296% 的拟合视频面积被额外裁掉。
2. 原有 `PlayerChromeInsets` 仅用 `minY < 100` 判断顶部障碍，没有判断障碍是否与标题栏相交。外屏右侧状态区也触发了标题栏整体下移；还额外叠加了区域已包含的 margins。
3. 长季集信息未限制换行，窄屏中会将标题栏撑高。

## 修改

- 全屏布局移除外层安全区域裁剪，并让布局明确接受当前父级提供的宽高；隐藏的控制面板占用 0×0 布局空间。
- 分区控制面板仍约束画面在自己的区域内，视频与 PGS 层在此模式下使用区域的实际尺寸。
- 只处理当前内容坐标内、实际与标题栏相交的活动遮挡。左、右边缘分别避让，不重复计算系统安全区域或 reserved region margins。
- 标题容器允许收缩，季集信息保持单行并截尾；不再撑大控制器。
- 新增仅限原创 Duo 验证数据的可见画面诊断，测量实际视频矩形穿过所有裁剪祖先后的可见面积。正式应用不执行该几何采样。

实现依据：[Apple ReservedRegion 文档](https://developer.apple.com/documentation/swiftui/reservedregion.md)说明 frame 使用当前视图坐标且已包含 margins；系统安全区域按各边分别处理。

## 已完成的验证

- `AdaptiveDisplayTests`：10 项通过，覆盖侧边状态区、顶部遮挡、非对称左右栏、网格与缩放焦点规则。
- 修复前 `Duo-Viewport-Before-20261119.xcresult`：裁剪断言失败，`croppedFraction=0.07296`。
- 修复后 `Duo-Viewport-After-Landscape-20261119.xcresult`：官方外屏横屏、1280×720 横版原创视频、长标题与季集信息检查通过。
- 同一原生播放会话切换横／竖屏，16:9 比例及 `croppedFraction=0` 保持；会话、渲染层、1 次打开、音轨、1.5 倍速和暂停位置保持。对应原始快照为 `native-landscape.json` 与 `native-portrait.json`。
- `Duo-Viewport-Expanded-Panel-20261119.xcresult`：官方 Open 姿态下默认全屏、打开／关闭控制面板、自动显隐、时钟推进及播放状态保持通过。

补充的外屏连续旋转测试最初等待 AX 矩形宽高交换，但 AX 使用物理显示屏坐标，界面旋转后该矩形可能保持不变。该次失败不计为通过；等待条件已改为播放器方向入口实际更新，再检查比例、裁剪量及会话保持。

最终回归共 7 个 UI 用例通过：包括上述横版原生播放、展开屏面板，以及外屏原生竖版、VLC 横版和竖版的两次连续旋转、普通 iPhone 17／iOS 26.3 连续旋转和 VLC 横版补充检查。断言覆盖画面比例、裁剪量、标题高度、控制器可触达性，以及会话、渲染层、打开次数、音轨、倍速和暂停位置保持。

外屏收尾使用新建的官方 iPhone Duo／iOS 27.1 模拟器，其默认姿态为 Closed；未通过窗口缩放或自定义尺寸模拟折叠状态。展开屏使用原官方模拟器的 Open 按钮验收。两种姿态分别通过；本轮不将它们表述为同一播放会话的折叠连续性验证。

旋转后的 `app.screenshot()` XCTest 附件存在物理屏坐标错位，因此不作为画面验收证据。已直接采集活动显示屏原始截图复核：原生截图 `03`、`04`，展开屏截图 `05`，VLC 横／竖屏截图 `06`、`07`。VLC 横屏原始截图为 2034×1398，竖屏为 1398×2034；16:9 画面完整，横竖切换未增加裁剪，同一会话与播放设置保持。图片未经合成或裁切。
