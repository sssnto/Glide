# Jellyfin 旋转后 HEVC 播放修复

## 已确认的问题

用户指定的视频由 Jellyfin 插件旋转保存后，在 Glide 自动播放失败。通过手机中已有的连接精确匹配文件，只读取元数据并短时播放；没有执行旋转、还原、替换或其他媒体写入。

原片为 HEVC Main 8-bit、`hev1`、SDR、1920×1080、60 fps。旋转后 Jellyfin 将容器报告为 `mov`，自动协商返回 `SupportsDirectPlay=true`，并省略 `TranscodingUrl`。

客户端已有策略会对 MP4/MOV 内的 `hev1` 优先使用原画重封装，但错误地假定服务器同时返回了 HLS 地址。结果在安装播放器前就抛出通用错误，恢复流程直接跳到视频转码。此视频的原画直放实际表现为时钟和声音继续、60 秒内没有视频帧；1080p 视频转码在此次测试窗口内也未输出视频帧。

显式请求原画兼容则成功：服务器提供 HEVC 视频复制的 fMP4 HLS，iPhone 输出 `hvc1` 视频帧。这说明该文件在此播放位置仍能解码，此次失败不需要重新旋转或恢复备份。该结论不等同于对整段视频的完整性校验。

## 修复行为

`MediaClient.playback` 在自动播放遇到上述组合时，重新以 `.compatible` 协商，并绑定同一媒体版本、保留原有轨道选择。该路径仍通过 `OriginalTransportPolicy.videoCopyURL` 严格验证视频复制；服务器无法复制时沿用已有失败恢复流程。

- 仅在客户端已判定为可疑 `hev1` MP4/MOV、服务器确认可直放、没有 HLS 地址、无需服务器选轨时触发。
- 原画预加载 `directOnly` 不触发该请求，避免对尚未选中的视频开启服务器任务。
- 手动原画、已有 HLS 协商、多音轨和字幕选择仍沿用原有规则。
- 不修改服务器文件，不需要升级 Jellyfin 插件。

诊断入口增加了受明确启动参数控制的精确路径匹配，导出的报告不含主机、媒体路径、片名、媒体标识或凭证。网络检查限定为 HLS 清单，避免误把原视频当成清单读取。

## 验证结果

独立包 `com.songpeng.glide.compatibilityqa`，版本 `2.0.0 (5)`；实体 iPhone 13 Pro Max / iOS 27.2 / Jellyfin 12.2.0。

| 检查 | 结果 |
| --- | --- |
| 修复前自动路线 | 协商失败，无可用资源 |
| 修复前手动原画 | 声音/时钟继续，60 秒内未显示视频帧 |
| 显式原画兼容 | 成功显示 HEVC `hvc1` 视频帧 |
| 修复后完整生产控制器自动播放 | 成功，约 6.79 秒显示首帧；实际播放超过 2 秒 |
| 旋转结果 | 播放输出 1080×1920，保留竖向显示 |
| 画质/传输 | HEVC 原画复制，音频转换；未进入视频降级转码 |
| 此次起播窗口内缓冲/掉帧 | 重缓冲 0，丢帧 0，恢复次数 0 |
| Swift 核心回归 | 11 项 XCTest + 295 项 Swift Testing 全部通过 |

另以原创 1080p60 HEVC `hev1` 短片调用生产插件的 `VideoMatrix` 修改旋转矩阵：ffprobe 正确识别 90° 旋转，FFmpeg 解码通过，转码输出 1080×1920。该测试没有读取用户的媒体内容。

本次是指定故障片段的起播修复验证，没有将短时播放结果扩展为长时间或所有 HEVC 视频均已验证的结论。

脱敏对照报告见 `Testing/Rotated-HEVC-2026-11-17/before-fix.json`、`after-fix.json`。

## 主应用更新状态

`Glide / Release` 的 `2.0.0 (5)` 已构建成功，通过深层签名检查。用户重新连接后，已成功覆盖安装主应用 `com.songpeng.glide`，保留原有数据。随后自动启动被 iOS 锁屏拒绝；用户解锁后可直接打开 Glide 复测，无需再次安装。原片的完整生产控制器验证已在上述独立包完成。
