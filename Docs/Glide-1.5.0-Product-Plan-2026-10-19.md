# Glide 1.5.0 能力规划：NAS 直连与连续观看

日期：2026-10-19。状态：已获用户确认，正在实现与验收；工程版本已设为 1.5.0。真实 NAS 由用户在独立 iPhone 验证包中测试，未通过全部门槛前不标记可发布。

下一功能版采用 1.5.0，主线是“连接 NAS 共享目录，直接播放和连续刷看”。现有竖版预览、媒体／目录切换、固定目录、收藏与播放队列延伸到 SMB 来源。字幕自动匹配与记忆按独立验收项推进，主线完成后可拆为 1.5.1。

## 1. 当前基线与判断

Apple 公开接口本日返回 Glide 商店版本 1.4.0，更新时间为 2026-10-17；代码标签 1.4.0 指向 fb88774。工作区另有 10 月 19 日的 MobileVLCKit 头文件告警修订。代码标签、公开版本和未提交维护改动分别记录，不把规划写成已交付。

| 当前能力 | 本轮判断 |
| --- | --- |
| Jellyfin、本地导入、授权目录、既有 WebDAV | 已有用户流程，继续复用。WebDAV 增强按此前决定暂缓。 |
| 本地系统／VLC 播放与中文字幕修复 | 已接入。VLC 适配器仍明确要求本地 file URL，不具备已验收的远程播放入口。 |
| 竖版目录／媒体、默认媒体视图、底部快捷操作 | 已完成 1.4.0 改版，下一版沿用这套交互。 |
| 外挂字幕 | 已有当前视频的 UTF-8 SRT/VTT 导入、延迟和底部位置调整；尚缺同目录自动匹配、视频级持久记忆。 |
| 目录收藏、范围、排序、随机与上下滑动 | 已有能力；新来源要完整接入，不重复列为全新功能。 |
| SMB、独立链接／STRM、片头片尾跳过、云同步 | 仍未形成对应的完整用户流程。 |

源码依据：Glide/Core/Models.swift、Glide/Core/MediaSource.swift、Glide/Services/SourceProvider.swift、Glide/Services/PlaybackResource.swift、Glide/Core/PlaybackEngineModels.swift、Glide/Services/Compatibility/VLCPlaybackEngine.swift、Glide/Views/PlayerView.swift。

SenPlayer 本日公开接口返回 6.2.3，商店仍声明 SMB、多媒体服务器及多平台能力；这里只将公开声明作为对标依据，没有进行同素材性能比较。[Glide 商店](https://apps.apple.com/cn/app/id6814679647)、[SenPlayer 商店](https://apps.apple.com/us/app/senplayer-media-player/id6443975850)。

### 为什么优先 SMB

它增加一种用户能直接感知的内容接入方式，并与 Glide 已有的目录刷看结合。可传播的完整流程是“连接 NAS → 进入视频目录 → 点开播放 → 上滑继续看”，也对应 SMB 播放器、NAS 视频播放器等准确的搜索意图。

这个排序属于产品判断，依据是现有能力缺口与用户的 NAS／本地视频场景。实际新增安装、转化和留存价值仍需试用及商店数据验证，目前没有搜索量或转化率数据支撑量化收益。

## 2. 1.5.0 必交付能力

| 优先级 | 能力 | 用户流程与完成定义 |
| --- | --- | --- |
| P0 | SMB 2/3 来源 | 手动输入 NAS 地址，选择或填写共享目录；支持普通账号及服务器允许的访客方式；可测试连接、保存、重新认证和移除。 |
| P0 | 媒体与目录浏览 | 沿用 2:3 竖版预览，进入默认媒体，顶部切换目录；支持中文文件名、排序、当前范围搜索和子目录范围。大目录读取有进度，可取消。 |
| P0 | NAS 流式播放 | 视频按需读取、出画面、暂停、拖动和续播；直接播放无需先下载完整文件。覆盖明确验证过的 MP4 与 MKV 组合，并显示实际所用播放器。 |
| P0 | 连续观看和个人记录 | 同一范围顺序／随机播放、上下切换、固定目录、视频收藏和观看进度接入 SMB；重启后可恢复来源与目录。家庭刷看沿用现有历史记录策略。 |
| P0 | 网络异常处理 | 区分认证失败、权限不足、文件不存在、读取超时和格式不支持；断网后显示可恢复状态，恢复连接后可继续；退出与切片取消旧读取。 |

SMB 使用只读访问。初版围绕局域网中的已知地址与共享目录，不加入远端文件删除、重命名或完整文件管理器。来源名称、服务器地址、共享路径和账号身份分开存储，密码使用现有 Keychain 路径；错误诊断继续脱敏。

### 格式承诺

首批验收素材至少包含 1080p MP4/H.264/AAC、4K SDR MP4/HEVC/AAC，以及带内嵌 ASS 和多音轨的 MKV。发布时以通过的封装、编码、字幕、设备组合形成支持表。SMB 协议接入不等于新增转码服务，也不能直接宣称全部 4K/HDR、杜比或所有 MKV 均可播放。

“原画兼容传输”继续表示 Jellyfin 的供流路线；“兼容播放”表示解码播放器。新 SMB 状态明确写来源与播放方式，减少用户将这两个概念混淆。

## 3. 配套增量：外挂字幕匹配与记忆

优先级 P1，适用于本地授权目录与新 SMB 来源：

- 识别同目录的同名 UTF-8 SRT/VTT，可根据语言偏好选择；多候选时供用户确认。
- 记住视频所选字幕和延迟，再次打开时恢复，提供清除选择的入口。
- 手动导入字幕形成受管理的本机副本，避免重启后文件授权失效；原有 2 MB 限制与明确的解析失败反馈继续保留。
- 保存身份包含来源、账号、共享目录及媒体位置，避免同名视频之间串用字幕；文件变化或删除时给出失效反馈。
- 内嵌 ASS 沿用已验证的兼容渲染。外挂 ASS、双字幕、字幕在线搜索与 PiP／AirPlay 中的外挂字幕属于后续专项。

此项独立验收。若拉长主线，应以 1.5.1 交付；1.5.0 发布说明只列实际完成的功能。

## 4. 先验证的技术门槛

SMB 需要同时实现目录访问和可定位的播放读取。现有 DirectorySourceProvider 只覆盖目录枚举；PlaybackResource 的本地授权与网络请求头，也没有表达 SMB 会话租约、随机读取和独立取消的完整契约。

先交一个端到端验证包，再确定实现路线与排期：

1. 连接一个合成 Samba 共享和一台真实 NAS，完成列目录、读取指定字节范围、取消与重连。
2. 从共享直接播放 1080p MP4 和带 ASS 的 MKV，拖动到后半段；验证不会等待完整文件下载。
3. 验证现有固定 VLC SDK 的网络访问能力，以及凭据隔离、切片释放、字幕时钟和断网恢复。目录客户端、播放读取和解码器的职责分别核实。
4. 比较直接访问与统一读取适配方案，按首帧、定位、取消、内存和认证结果选择。只有通过验证的 SMB 资源进入网络兼容路线；本地及 Jellyfin 播放策略保持各自边界。
5. 新依赖完成 Swift 6／iOS 17 编译、架构、版本锁定和分发材料检查后接入。AMSMB2／libsmb2 是候选，不在规划阶段认定已可用于生产。

libsmb2 官方资料声明支持 SMB2/3、异步读取和签名／加密选项，AMSMB2 提供指定范围与偏移读取接口。这说明存在实现候选，仍需验证所选版本与 iOS 打包结果。[libsmb2 官方仓库](https://github.com/sahlberg/libsmb2)、[AMSMB2 读取接口](https://github.com/amosavian/AMSMB2/blob/master/AMSMB2/AMSMB2.swift)。

验证包未通过时继续处理相应阻塞，不将只有登录或目录列表的实现视作“NAS 直连播放”完成。

## 5. 交互与性能约束

- 添加来源沿用当前入口，SMB 表单优先展示地址、共享目录和账号；域等次要参数按需展开。
- 打开来源后保持 1.4.0 的默认媒体视图。连接测试与保存复用连接结果，错误直接定位到相应字段。
- 读取目录和封面异步进行，可见卡片优先；显示已获得的内容与扫描进度。深层搜索说明当前范围，支持停止扫描。
- SMB 文件没有服务器影视元数据时，先显示真实文件名、路径层级和已读取的规格，不伪造年份、评分或影视海报。独立影视刮削另行规划。
- 新会话、切片、搜索和缩略图沿用失效令牌；旧网络回调不能覆盖当前媒体。缓存与读取并发有上限。
- 凭据不写入可复制 URL、播放日志或导出诊断。签名／加密要求通过明确的支持矩阵验证；不满足时显示可理解的连接错误。

## 6. 验收标准

以下是发布门槛与待测目标，不是当前性能结果。

| 场景 | 通过条件 |
| --- | --- |
| 服务端与认证 | 合成 Samba 与至少一种真实 NAS 通过；覆盖 SMB2／SMB3、普通账号、允许访客、错误密码、无权限共享和要求签名／加密的场景，记录实际支持范围。 |
| 大目录与路径 | 至少 1000 个条目、三级子目录，含中文、空格、特殊字符和同名文件；读取有反馈、可取消，结果身份稳定，目录根范围正确。 |
| 流式读取 | 大文件首帧前无需完整下载；跳到 70% 可直接读取相关范围；取消后不继续无限拉取，短读和 EOF 正确处理。 |
| 首帧与定位 | 在 NAS 持续读取能力至少为素材平均码率两倍的受控局域网中，1080p 首帧目标不超过 5 秒；成功拖动 20 次，最后一次定位意图生效。记录设备、素材、吞吐与实际结果。 |
| 长播与切片 | 30 分钟连续播放、50 次切片／退出重开；没有崩溃或持续卡死，内存不随播放时长持续线性增长，退出后连接与读取可释放。 |
| 网络恢复 | 至少 5 轮中断／恢复、NAS 休眠唤醒、文件被移除；错误反馈可理解，恢复位置和暂停意图正确，认证错误不自动无限重试。 |
| 现有能力回归 | 本地原生／VLC、中文字幕、Jellyfin 原画兼容与重试、离线播放、既有 WebDAV、目录默认视图均保留。 |
| 设备 | 主要使用现有 iPhone 13 Pro Max 真机；iPad 完成布局及真实网络播放验证。设备不足时明确缺项，不将模拟器结果写作真机结果。 |

字幕配套另验收：多语言候选、重启记忆、字幕文件失效、源文件变化、切换视频不串字幕，以及系统／兼容播放的时钟对齐。

技术验证后再给出日历排期。当前没有新增默认遥测；试用阶段通过志愿用户反馈和已有脱敏诊断观察连接失败、首帧与重复使用。建议找 5 位有 NAS 的用户完成真实任务，观察一周内是否有至少 3 位主动再次使用；这是小样本产品门槛，不是市场效果证明。

商店表达可围绕“SMB 直连 NAS，打开目录就能刷”。发布后对比相同口径的搜索来源、产品页访问与下载转化；样本不足时延长观察，候选检索词使用已验收的能力。

| 版本 | 主要能力 |
| --- | --- |
| 1.4.x 维护 | 根据 1.4.0 真实反馈处理阻断使用的回归；已完成的构建告警修订随下一构建交付。 |
| 1.5.0 | 本计划的 SMB 直连、流式播放与既有刷看流程接入。 |
| 1.5.1（按拆分需要） | 外挂字幕自动匹配与视频级记忆。 |
| 1.6 | 独立 HTTP(S) 链接／STRM、手动片头片尾规则；Jellyfin 有媒体片段标记时显示相应跳过入口。 |
| 1.7 及后续 | Emby、Plex、飞牛逐项验收；FTP、网盘、IPTV、同步和平台扩展沿长期对齐路线独立排期。 |

Jellyfin 的媒体片段能力依赖服务器版本、提供方与已生成的标记。后续跳过功能先做手动规则和真实标记，不把它描述为客户端自动识别片头。[Jellyfin Media segments](https://jellyfin.org/docs/general/server/metadata/media-segments/)。

用户此前明确暂缓的 WebDAV 增强和收费保持原安排。私人刷看频道、精彩时间点收藏保留为增长候选，待真实复用证据充分后单独做版本；全局搜索、多端同步和大规模重构不作为本版主线。

旧 SenPlayer 规划中的版本号与实际 1.4.0 UI 版本发生错位，后续顺序以本计划为准。长期全部能力对齐的目标继续保留；本版推进 S04 的 SMB 部分与 P01 的受限网络兼容，其他协议和高级输出仍分别验收。


## 9. 实施决定（2026-10-19）

- SMB 与既有 WebDAV 在 1.5.0 同时提供。SMB 新增直连，WebDAV 保留既有认证、目录与系统播放路线并回归；WebDAV 扩展仍不纳入本版。
- 复用固定 MobileVLCKit 3.7.3 中的 libsmb2 4.0.0。只增加未修改的公开头文件和只读桥接，不引入第二套 SMB 二进制；设备与模拟器的 22 个必要符号、头文件校验另有脚本和报告。
- 目录与限长范围读取由独立上下文承担；播放采用 SDK 自带 SMB 访问模块。备选 NSInputStream 方案在固定 VLCKit 的 `open_cb` 中把长度设为 UINT64_MAX，不能向播放器提供已知文件长度，故未选择为生产入口；没有宣称做过两种方案的同素材性能 A/B。源码核查与直接方案实测是这次选择的依据。
- 播放 URL 不含账号密码；内部只附加固定的 `timeout=12`，主动要求加密时附加 `seal`。账号、域和密码通过内存中的媒体选项传递。SDK 原始 SMB 错误不加入导出诊断，只保留已分类的错误。
- 元数据／图片读取并发限制为 4；单次读取最多 1 MiB，图片上限 8 MiB。目录扫描按批更新，支持停止；退出／切换视频继续使用既有异步退役和失效令牌。
- SMB 视频强制走已验证的兼容入口；Jellyfin 与 WebDAV 的系统播放路线保留。兼容入口不承诺 PiP、AirPlay 或系统时间轴预览。
- 文件来源新增可选择的“记住播放进度”，默认关闭以保留家庭刷看行为；开启后复用本机最近观看、进度及恢复。不会向 NAS 写入进度文件。
- 外挂字幕自动匹配与视频级字幕记忆明确安排到 1.5.1，本版继续保留原有手动字幕能力。1.5.0 的发布材料不将它们列为已交付。

验收记录持续写入 [1.5.0 验收目录](Testing/Glide-1.5.0/)。模拟器、合成 Samba、物理 iPhone、真实 NAS 分别记录，不相互替代。

2026-10-20 后续：字幕自动匹配与视频级记忆已在独立的 [1.5.1 计划](Glide-1.5.1-Product-Plan-2026-10-20.md)中实施，结果见 [1.5.1 验收](Testing/Glide-1.5.1/README.md)。1.5.0 的历史验收范围不因此扩大。
