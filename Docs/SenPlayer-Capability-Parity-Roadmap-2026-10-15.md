## 2. 主要判断

Glide 已有影视浏览、目录刷看、基本字幕／音轨、续播、离线管理和原生系统播放基础。完整对齐需要增加四类基础设施：

1. **来源适配层**：从两个来源扩展到本地、NAS、多个媒体服务器、网盘与直播。
2. **可替换播放内核**：解决本机格式、字幕渲染、原盘与高级画质需求，同时保留现有原生路线。
3. **统一资源与数据模型**：支撑跨来源查找、版本／线路、下载、收藏和多端同步。
4. **平台适配层**：将当前 UIKit／iOS 生命周期逻辑与业务分离，分别完成 Mac、TV 和空间设备体验。

“有画中画入口”“能打开某个 MKV”“系统接受一个缓冲目标”分别只代表一个环节。全量对齐必须覆盖字幕、音轨、定位、网络波动、退出、重启和平台差异。

### 3.4 仍需实测的项目

以下不计为已确认的 SenPlayer 稳定版能力，也不提前算 Glide 的确定差距：

- 倍速精确上限、A–B 循环、定时停止、截图笔记的当前入口与范围。
- NFS／SFTP 是否直接支持；FTP 与 SFTP 分开核实。
- 图形字幕格式、双字幕的特殊样式限制、字幕遮挡的实际含义。
- DLNA 的设备范围、字幕与认证传递；S3 有介绍，需稳定版实测。
- IPTV 的 M3U／TXT 格式、节目单、时移与回看边界。
- 批量下载、暂停／重试／后台调度、已下载字幕与跨端状态。
- 本地图片的格式、Live Photo／RAW／幻灯片；相册视频入口不能代表完整照片管理。
- 云盘登录方式、会员限制、写入功能、原画／转码和文件下载差异。
- AI 字幕生成／翻译是否已经进入稳定版；当前不由社区预告或 SDK 能力计入。
- Vision 的兼容 App 与原生 App 差别；Android／Windows 未见可靠上架证据，暂不扩成目标平台。

这些条目在 M0 分配实测记录，确认后加入对应工作包。公开资料无法证明隐藏功能已全部枚举，因此“全量”以完成稳定版实测冻结后的清单为准。

## 4. 技术路线与关键决策

### 4.1 来源与资源身份先统一

新增 `SourceProvider`，按浏览、搜索、读取、播放协商、下载、进度、文件写入等声明能力。NAS、云盘、媒体服务器、直播各自实现适配器，页面按能力展示操作。

资源身份区分来源实例、账号、内容、文件版本与线路。Jellyfin／Emby／Plex 的 ID 不混用，也不按文件名或片名合并。临时地址、认证头与可刷新凭据属于解析结果，不成为持久内容身份。

继续保留家庭刷看、电影单片与节目队列三类观看语义。协议接入、播放解码和影视元数据分别设计，避免“支持 SMB”同时暗含“支持所有文件格式和自动海报”。

### 4.2 播放内核先做受控比较

提取 `PlaybackEngine`，暴露准备、播放、定位、速率、轨道、缓冲、输出格式与可用系统能力；现有 AVPlayer 成为一个实现。新内核先在实验构建比较，不直接替换默认路线。

候选：

| 路线 | 价值 | 必须验证 |
| --- | --- | --- |
| 现有 AVPlayer | 延续已做的原生集成、HDR 修订与系统输出 | 格式边界与兼容回退，不能承担全部高级需求 |
| 授权的 KSPlayer 路线 | 项目公开列 Apple 平台、AVPlayer／FFmpeg 路线；SenPlayer 位于授权应用名单 | 具体授权、可用模块与自家素材测试，不能据此认定 SenPlayer 6.2.3 的实际内部架构 |
| libmpv／FFmpeg／libass 组合 | 广格式与渲染控制候选 | iOS 集成、系统输出、字幕、生命周期、功耗和构建选项 |

[KSPlayer 项目](https://github.com/kingslay/KSPlayer)列出了不同许可和付费模块；[mpv 项目](https://github.com/mpv-player/mpv)也区分构建许可。选型时确定可采用的授权与二进制组成，不能只比较示例能否播放。上述为工程依赖检查，不是本次已经完成集成或取得授权。

M0 只选一条兼容路线进入实现，避免同时维护多个新内核。Jellyfin 服务端转码继续作为一条真实可用路线；当用户指定原画或有可用本机路径时，不能为了省实现自动把能力差距隐藏成转码。

### 4.3 三种缓存独立管理

- 元数据／海报：现有 MediaCache／ArtworkCache，TTL 与容量已存在。
- 流媒体缓存：新增分段或字节范围索引，识别内容版本、账号、文件变化与过期签名地址。
- 离线文件：用户主动下载，具有完成校验和独立保留／删除语义。

统一存储预算与状态展示，但不让“清理临时缓存”删除离线文件。当前 `preferredForwardBufferDuration` 不能替代磁盘缓存；下一条资产准备也不能宣称整段视频已缓存。

### 4.4 同步、隐私和平台基础

`LibraryStore` 的来源、观看记录、目录规则拆为可迁移 Repository，先完成可靠本机持久化，再建设同步队列。iCloud 同步按字段规定策略，删除保留墓碑、旧修订不可覆盖新修订，家庭刷看继续保持默认不上传观看进度。

私密来源必须从列表、搜索、首页、历史、缓存预览与 App 切换器同时受控；不能只给入口加密码。同步锁定状态与分享／外部打开的行为需明确。

UIKit、AVAudioSession、屏幕旋转、下载后台回调和窗口逻辑从领域层隔离。Mac 与 TV 各自设计输入／焦点／窗口行为；共用模型和服务，不把手机页面直接拉宽就记作平台完成。

## 5. 分阶段长期路线

版本号为工作包建议，未预留、未修改工程版本，也不代表已承诺上线日期。M0–M8 是工作包，实际可跨多个小版本；后续阶段保留全量目标。

### 粗略投入与排期假设

按一名熟悉项目的开发者持续投入、可获取测试设备估算：

- M0：1–2 周，先降低内核、网盘和高级画质的不确定性。
- M1/M2：约 8–12 周，形成第一轮可体验的能力扩展。
- M3–M6：约 20–32 周，服务与提供方逐项交付。
- M7/M8：约 16–28 周以上，平台与高级能力不确定性最高。

总量是 **多季度、约 12–18 个月以上**的单人产品线投入量级，置信度低，不是交付承诺，也不是简单累加就能覆盖所有未知项。外部服务授权、可用 SDK／模型、许可、设备采购和平台分发可能另行影响；M0 完成后重新估算。每个小版本仍应单独可用，避免等待全部完成才发布。

## 6. 首批开发规格

最初建议先完成 **M0 + M1，随后交付 M2 的本地／SMB 与时间轴预览**。用户授权实施后，先交付不依赖内核选型的本地观看闭环；最初 1.2.0 批次未接入新 SDK；之后 1.3.0 已接入本地兼容内核，M0 与 M1 余项继续保留。实际分包以本稿顶部进度和最新功能规格为准。

| 工作项 | 当前落点 | 交付标准 |
| --- | --- | --- |
| 来源能力协议 | `Core/Models.swift`、`Services/MediaClient.swift` | 新来源不要求页面遍布 `kind == .jellyfin` 分支；旧来源回归通过 |
| 内核接口 | `Services/PlaybackController.swift`、`Views/VideoSurface.swift` | 统一状态和取消；快速开关无旧画面／声音；保留诊断与现有恢复 |
| 数据仓储 | `LibraryStore.swift`、`Services/DownloadStore.swift` | 迁移可回退、写失败可见、稳定身份与下载文件不误丢 |
| 本地／SMB | 新适配器与来源 UI | 长目录、授权恢复、随机定位、断线重连和原生支持边界完整 |
| 时间轴预览 | 新预览服务与 `PlayerView.swift` | 选定时间与缩略图一致，有请求／磁盘上限，拖动不压垮当前播放 |

预览先验证 Jellyfin 已有预览资源是否可复用，再做受限的本地生成。不要为了每张缩略图读取完整远端影片，也不在第一帧前批量生成。

## 7. 每项如何证明“对齐”

建立 `ParityCase` 验收记录：能力 ID、SenPlayer 版本／平台、Glide 构建、源类型、文件参数、设备、步骤、结果、日志与限制。

1. **入口**：用户能找到能力，并理解当前来源是否支持。
2. **正常路径**：同一素材、服务器、账号权限与网络下完成同一任务。
3. **异常路径**：取消、登录过期、断网、存储不足和旧回调有确定结果。
4. **生命周期**：切集、倍速、定位、后台／前台、关闭与重启不丢状态或占用资源。
5. **系统输出**：字幕／音轨／颜色在 App、画中画、AirPlay／外屏分别核对。
6. **性能**：记录冷／热首帧、定位响应、卡顿、峰值内存与长时间温度／耗电，不只比较画面是否出现。

核心样片覆盖 MP4／MOV／MKV、H.264／HEVC Main10、不同 HDR／DV profile、常见音频、文字／图形字幕与一组原盘素材。测试前记录片源实际参数；支持列表必须落实到具体组合。

来源测试覆盖深目录、大库分页、中文／特殊字符、Range、过期地址、授权失效与切账号。同步测试覆盖双设备同时修改、离线后上线、删除、来源重建；文件删除与本机历史移除分别测试。

Glide 既有差异化作为每批回归门槛：上下刷看、一轮不重复、范围不越界、跨季选集、放大后拖动、锁定和默认不记录家庭刷看历史。普通播放模式可新增手势配置，但不默默改变这些既有约定。
