# Jellyfin 家庭视频批量文件整理

日期：2026-11-16。范围由用户确认：Jellyfin 家庭视频。客户端保留前一轮 4K 预加载改动；服务端配套 Glide Toolkit 1.2.0，面向 Jellyfin 12.2 / Linux Docker。

## 使用方式

1. 在原家庭视频网格点“选择”，对照当前缩略图勾选；底部可移动、删除或继续使用原有旋转。
2. “移动”选择 Jellyfin 已入库、当前用户可见的目标目录，显示实际原文件名与同名外挂字幕数量，再确认提交。
3. “删除”将原文件及同名外挂字幕移到原目录下 `.glide-trash`，不是只删本机记录。它仍占 NAS 空间，不永久清空，可在整理任务还原。
4. 任务入口：片库更多菜单 → 文件整理任务，或任务页 → 文件整理 → 对应服务器。显示总数、完成、待处理、失败和逐项原因。
5. 可暂停后续、继续、取消未开始项、仅重试失败项；已完成项不再执行。还原也建立服务器队列，不覆盖原目录后来出现的文件。

## 边界与性能

- 每批 1–500 个，只选择已加载条目；不为全选扫描整个 NAS。
- 服务器逐个处理、持久化任务；退出客户端继续执行，手机不下载上传大视频。
- 移动限同一媒体库根及文件系统，使用原生 no-replace rename，不跨盘复制删除。目标同名拒绝该项；跨盘、符号链接、无法定位唯一主文件时拒绝。
- 支持 MP4、MOV、M4V、MKV、AVI、TS、M2TS、WebM 的家庭视频主文件。电影、剧集、多版本条目不提供此能力。
- 同名或带语言后缀的 SRT、ASS、SSA、VTT、SUP、SUB、IDX 一起处理；最多 32 个外挂字幕。海报、NFO 和历史方向备份不自动搬动。
- 保留服务器历史方向备份位置。需要旧方向还原时先将视频还原到原目录。路径变化可能产生新的 Jellyfin 条目 ID，其他客户端的收藏、历史绑定未自动迁移。
- 与旋转任务共享写入锁；播放中的文件、旋转队列占用文件拒绝整理。当前文件完成后才响应暂停与取消，不打断原生移动。
- 每个文件组在修改前持久化源、目标及版本；分组部分失败尝试反向 no-replace 回滚。重启核对源和目标，矛盾结果标为需核对，不盲目重做。
- 版本由长度、修改时间及头尾各最多 64 KiB 摘要组成，用于识别正常并发修改，不是对任意外部恶意写入的全文件 CAS。
- 移动完成后合并更新受影响目录的直接子项，不逐视频扫描整个媒体库。索引更新失败会显示待更新并延后重试。
- 服务端默认关闭文件整理；管理员单独开启，普通用户需独立授权。现有旋转授权不会获得文件整理权限。仍受原有可见媒体库和管理员 AllowedRoots 限制。
- 不提供永久清空回收站；请保留配置数据目录 `glide-file-actions` 和媒体旁的 `.glide-trash`，以便恢复。

## 安装

在 Jellyfin 的插件存储库中使用原地址：

```text
https://raw.githubusercontent.com/sssnto/GlideToolkit/main/manifest.json
```

等已有旋转／整理任务完成后，安装目录中的 1.2.0 并重启容器。管理员在 Glide Video Toolkit 设置开启“家庭视频文件整理”；如非管理员在 Glide 登录，填写允许整理的用户 ID。需要媒体卷及文件可写。
