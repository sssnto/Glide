# Glide 下一版本产品设计规划

日期：2026-10-09。状态：已按[详细功能规格](Glide-1.1.0-Functional-Spec.md)完成本轮开发与 HDR 色彩修订，用户确认测试完成并授权提交 GitHub。本文保留产品目标与后置项；实际交付范围、验证结果分别以功能规格和[开发验证报告](Testing/Glide-1.1.0-验证报告.md)为准。

版本：**1.1.0 · 连续观看**，本地开发构建 **1.1.0（4）**。构建 2、3 已提交 GitHub；构建 4 修正缓冲恢复后过早转码，独立验证见[缓冲恢复回归](Testing/Glide-1.1.0-缓冲恢复验证-2026-10-10.md)。设计基线为 1.0.2（4），提交 `6191249`；本文件不代表 App Store 当前上线版本。

## 1. 版本目标

让用户连接自己的 Jellyfin 后，能够快速找到内容、持续观看，并在退出后自然回到原来的位置。家庭视频继续突出任意目录刷看；电影与剧集保持作品详情、续播与选集逻辑。

本版围绕三个体验目标：

1. **少等待**：起播、下一条、倍速和拖动都有稳定且可解释的反馈。
2. **少操作**：常用目录一键开刷，剧集优先回到应继续观看的集。
3. **不丢上下文**：返回保持浏览位置，刷新保持已有内容，离线保留必要的封面与信息。

继续只使用 AVFoundation / AVKit 原生能力。默认自动选择可用播放路线，不要求用户在原画、重封装、转码之间反复选择。收费入口继续隐藏。

## 4. 信息架构与页面设计

保留 iPhone 的「片库／继续与收藏／离线／设置」四个入口，iPad 使用侧栏。通过内容层级调整提高效率，避免再建立一套重复导航。

### 4.1 片库首页

从上到下依次展示：

- 当前来源：单行名称与切换入口。多个来源不合并成无边界的刷看队列。
- 常用刷看：仅在用户固定了家庭目录时出现，使用小型横向卡片，名称出现一次。
- 媒体库：保留封面网格，展示名称和电影／节目／家庭视频类型。

不在首页增加大型自动播放宣传卡片。继续观看集中在原有个人页；首页常用刷看不保存家庭视频观看历史。

### 4.2 家庭目录

保留「目录／视频」切换，名称与添加时间排序继续可用。

| 区域 | 设计规则 |
| --- | --- |
| 顶部 | 目录名、返回与紧凑路径；超长路径可横向查看 |
| 视图切换 | 目录／视频互斥展示，避免目录占满视频浏览空间 |
| 目录卡片 | 预览图、单次目录名；缺图有稳定占位，不为取得封面阻塞列表 |
| 视频卡片 | 保留完整画面比例；横竖混合使用有界图片区域和留白，不强行裁成正方形 |
| 范围栏 | 明确「本层／含子目录」、当前排序与顺序／随机；长列表中仍可快速找到开刷入口 |
| 返回 | 恢复对应目录、视图、筛选及可见条目；优先按条目 ID 恢复，避免分页变化造成错位 |
| 刷新 | 保留旧列表与位置，小范围显示更新状态；成功后合并新内容，失败保留可用列表 |

进入新目录及主动切换目录／视频时从顶部展示；从详情或播放器返回同一列表时恢复位置。刷新、旧请求返回和重新认证均不能把用户送到另一个范围。

### 4.3 常用刷看

扩展现有固定目录，不增加平行的“固定目录”和“刷看清单”两套管理入口。

目录菜单提供「设为常用刷看」。默认沿用当前目录、范围、排序和播放顺序；用户只需确认可选的显示名称。卡片可以直接开刷，也可以进入原目录。

保存的是来源／账号、目录 ID 和浏览规则，不是转码 URL、凭据或固定的视频下载集合。新增视频按原规则自动纳入，已删除条目忽略；目录失效显示“目录不可用”，提供重新选择和移除。

首版仅支持一个目录及其子目录，不组合多个媒体库。随机模式必须以完整范围为基础，一轮不重复；列表尚未收齐时不得把部分结果伪装成完整随机集合。

### 4.4 继续与收藏

保留两种视图。继续观看中的单集按节目聚合：节目海报、节目名、季集标识、该集进度。点击直接续播；次级入口进入节目详情和选集。

规则：优先继续最近观看但尚未完成的集；该集完成后选顺序上的下一集，包括跨季；全部完成则展示“已看完”，提供从头观看。特别篇不自动插入正片队列，首次需明确选择。

旧记录迁移以来源／账号／节目 ID 合并；缺少节目 ID 时保留原单集记录，按需补充信息，不能按名字误合并不同版本或不同来源。用户移除节目级继续记录时隐藏相关本机记录，不删除文件、不重置 Jellyfin 进度；再次播放可重新出现。

收藏继续支持单集和节目，不因继续观看的聚合自动修改已有收藏语义。

## 5. 播放器设计

### 5.1 控制台层级

| 层级 | 内容 |
| --- | --- |
| 顶部 | 返回、短标题、锁定、更多 |
| 底部常用区 | 同一条进度／缓冲轨道、时间、播放／暂停、前后跳转；家庭视频显示队列，剧集显示选集 |
| 播放设置 | 声音、字幕、速度、画面适应、旋转、画中画与 AirPlay |
| 视频信息／帮助 | 当前播放方式、源／输出信息、诊断导出；不要求普通用户理解解码参数 |

画面点击一次唤出控制台；设置或选集面板打开时不自动隐藏。横屏下优先使用一条紧凑底部操作栏，避免标题、操作和说明占据画面中央。

### 5.2 手势保持稳定

| 条件 | 手势 | 结果 |
| --- | --- | --- |
| 未锁定 | 单击 | 显示／隐藏控制台，不跳进度 |
| 未放大，家庭视频 | 上滑／下滑 | 下一条／上一条 |
| 未放大，剧集 | 上滑／下滑 | 下一集／上一集，支持跨季 |
| 未放大，电影 | 上滑／下滑 | 不切换无关作品 |
| 未放大 | 左右滑动 | 保留现有恢复正常／切换 2× 行为 |
| 未放大 | 长按左／右侧 | 按既有设置快退／快进，不影响短触 |
| 未锁定 | 双指捏合 | 放大／恢复画面 |
| 已放大 | 单指或双指拖动 | 只拖动画面，不切片、不改变速度 |
| 已锁定 | 单击 | 唤出可解锁入口，其余画面手势禁用 |

不重新引入亮度／音量滑动，不更换 VLC，不通过新增双击动作争抢已稳定的单击识别。

### 5.3 等待与失败反馈

首次进入立即展示当前视频预览和轻量准备状态，首帧后移除。播放中短暂缓冲保留最后一帧，不再次显示“正在准备画面”；较长等待显示“网络较慢，正在恢复”，只提供必要的取消／重试。

自动恢复保留播放位置、暂停意图与用户可延续的声音／字幕偏好。无法播放时，说明网络、登录、服务器转码权限或格式支持类别，技术错误码放在详情中。

合并进度条保留两个可区分的视觉层：已播放与实际已缓冲。多个不连续缓冲区间分别绘制，不能把目标缓冲秒数画成已缓存。拖到未缓冲范围允许等待，暂停拖动后保持暂停。

### 5.4 性能方案边界

优先测量点击至首帧的完整耗时，再拆分媒体协商、服务器准备、网络读取与解码阶段。不得只展示最后一次恢复的耗时。

下一条准备分级进行：先预取元数据与封面，再验证有限的原生资源准备是否改善首帧。默认只准备下一条；当前视频首帧、缓冲和定位优先。快速连续滑动、改变范围、退出播放器时取消过期任务。

不提前并行启动多条 Jellyfin 视频转码。蜂窝、低电量、持续缓冲时收缩预取；预取失败不妨碍当前播放。顺序与随机都只能在已确定的实际队列内准备，不跨目录猜测下一条。

倍速缓冲使用系统偏好与真实可用网络共同调整，设定上限；增加缓存不能掩盖设备不支持的编码，也不能承诺 AVPlayer 一定缓存到设定长度。

## 6. 追剧与离线的完整流程

### 6.1 追剧

节目详情主按钮改为明确的“继续第 X 季第 Y 集”或“播放第 1 集”，旁边保留选集。上下滑切集和选集面板延用现有能力。

语言偏好按语言、用途与可用轨道匹配下一集，不沿用文件级轨道编号。没有匹配项时使用该集可用默认，并在设置中展示真实结果。首末集不循环。

自然播完沿现有顺序推进；下一集提示和取消连播设置作为本工作包的后续增量，不能影响刷看即时上下切换，也不能盖住片尾字幕。

### 6.2 离线

下载前展示所选版本、预计空间（未知则明确标记）以及原生播放支持边界。下载失败、传输完成但校验失败、文件兼容性不足分开解释；不能仅凭扩展名承诺可播放。

离线页按“可播放／进行中／需处理”分组，显示队列、容量和主要操作。复用已有暂停、继续和重试；失败任务不自动无限重下。队列默认同时传输 1 个任务，后续再评估 Wi-Fi 并发收益。

下载完成保存必要的海报、片名、季集、时长与文件快照，断网或登录失效仍可查看兼容本地文件。删除来源时明确是否同时移除其离线文件，不能静默清掉已下载内容。

本版仍不承诺 MKV 全格式离线或 Jellyfin 转码 HLS 离线打包。批量选择剧集加入下载队列可后置；必须先保证单片下载、校验、重启、断网播放闭环可靠。

## 7. 验收与用户测试

以下是建议目标，尚未测得；先用 1.0.2（4）记录基线，再锁定可达门槛。用户测试记录设备、系统、构建、网络与服务器配置，不用一台模拟器的数据代替实机结论。

| 指标／场景 | 建议验收标准 |
| --- | --- |
| 首次直放 | 稳定局域网、已确认原生兼容素材，点击至首帧 P95 ≤3 秒，每类路线至少 30 次，区分冷／热状态 |
| 连续切片 | 相同素材、网络与设备对照；有预取的下一条首帧 P95 目标 ≤2 秒，快速切换不串音、不出旧画面 |
| 自动转码 | 单独记录服务器冷启动与热启动；受控测试环境总首帧 P95 目标 ≤8 秒，超标可分辨服务端／客户端原因 |
| 播放成功 | 固定支持范围内素材 100 次播放均成功；不支持素材显示可解释失败，不计为成功播放 |
| 倍速与定位 | 普通与 2× 各连续播放 10 分钟；已缓冲／未缓冲各拖动 10 次，最后定位有效，无无限等待 |
| 手势 | 连续隐藏／唤出 20 次，缩放拖动／恢复 20 次，锁定／解锁 20 次，无误快进、误切集或控制台失联 |
| 返回与刷新 | 大库深处进入详情、播放、返回各 20 次；不黑屏、不跳顶部，刷新失败仍可浏览旧内容 |
| 常用刷看 | 新增、改名、改排序、包含子目录、随机、目录新增／删除媒体、目录失效及重启均符合保存规则 |
| 节目续播 | 同名不同来源不误合并；跨季、特别篇、旧记录、移除记录和声音／字幕缺失有确定结果 |
| 离线 | 完成校验后重启、飞行模式、登录失效仍可播放兼容文件；缺文件／磁盘不足／失败重试不误报完成 |
| 长播与快切 | 实机连续播放 60 分钟、切换 100 次；无崩溃、不可恢复黑屏、持续增长的资源占用或退出后的旧声音 |
| iPad 与无障碍 | 分屏、旋转、较大字体、VoiceOver 的核心流程可操作；海报与字幕不覆盖主动作 |

首批设备至少包含用户日常使用的 iPhone 13 Pro Max、一台较新 iPhone 和一台 iPad；网络覆盖局域网 Wi-Fi、远程 Wi-Fi 与蜂窝。新增页面由至少 5 位目标用户完成“进入目录开刷、退出找回位置、继续节目、断网看下载”四个任务，记录失败步骤和需要解释的地方。

每次测试交付一个版本号明确的清单：新增功能、重点步骤、已知限制和反馈模板。支持用户主动分享脱敏诊断，不新增默认上传私人片名、地址或行为的分析 SDK。

不把计划中的能力当作已完成。P0 有阻断时先形成 1.0.x 修复版本，再进入 1.1.0 新功能发布；不为凑齐版本功能把不稳定的预取或批量下载强行带入。

## 9. 本版暂缓与后续验证

全库组合搜索、多个目录组成智能清单、家庭照片时间线、SMB、本地文件导入、iCloud 同步、Apple TV、第三方解码和收费均不进入本版承诺。

1.2 候选先验证“家庭照片＋视频回忆浏览”和“当前来源内统一搜索”哪个更常用。前者须明确是否使用拍摄时间、添加时间以及缺失日期回退；后者须明确范围并将单集合并为节目入口。两者都不能未经验证同时扩张为下一版全部范围。

商业化先通过真实使用验证：常用刷看是否被反复使用、用户是否愿意替换现有播放器、离线是否有明确高频场景。基础播放、兼容恢复和可靠性保持免费；没有明确价值与完成证据前不恢复 Pro 入口。

外部资料于 2026-10-09 核对，借鉴其层级和流程，不将其能力宣称为 Glide 已有能力：

- [Infuse 播放控制](https://support.firecore.com/hc/en-us/articles/215090987-Playback-Controls)：官方 iPhone／iPad 手势还包含亮度与音量；Glide 按既定刷看需求保留自己的上下切片、长按跳转和缩放后拖动规则。
- [Infuse 下载流程](https://support.firecore.com/hc/en-us/articles/215091037-Downloading-Files)：从详情发起下载并查看进度，支持随文件下载字幕；本版借鉴清晰的离线闭环，不据此承诺原生播放器解码范围。
- [Infuse 媒体组织](https://support.firecore.com/hc/en-us/articles/27862264977047-Library-Scanning-Indexing)：其扫描／索引设置不适用于 Jellyfin 连接。Glide 的 Jellyfin 元数据仍由服务器提供，家庭内容不做影视匹配，也不在首帧前强制深度扫描。
